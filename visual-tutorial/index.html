2

Intuition 直觉

这里的 intuition 是：attention 并不是模型在“理解世界”，而是在每一层 (every layer) 里 重新计算 token 之间的 relevance（相关性）。换句话说，每个 token 都在问： right now, who should I listen to?

注意力不是 memory，也不是 understanding。它是一个动态的、可学习的 routing 机制 (a dynamic, learnable routing mechanism)：根据当前内容，决定信息从哪些 token 流向哪些 token。

The key shift for a systems engineer: think of attention as a content-addressed lookup that runs fresh at every layer. Older models (RNNs) passed a single hidden state left-to-right through a keyhole. Attention instead lets every position read every other position in parallel and decide, by learned similarity, how much each one matters right now.

One-liner to remember: attention = a learned, per-token, per-layer soft lookup over the sequence. 不是理解，是 routing。

3

Analogy 类比

Picture walking into a library looking for books about dinosaurs.

Query (Q)

你的问题：“I want dinosaurs.” 当前 token 在寻找什么。

Key (K)

书架上的标签：“Science”, “History”. 每个 token 对外宣传自己是什么。

Value (V)

架子上真正的书。每个 token 携带的实际信息 (the payload)。

You compare your question (Q) to every shelf label (K). The better the match, the more books (V) you take from that shelf. You walk away with a weighted blend — not a single book. Even a poorly-matching shelf contributes a little. That blend is attention.

Where the analogy breaks 类比的边界

In a real library, someone else writes the labels and stocks the books. In attention, each token creates its own Q, K, and V at the same time — they are three learned projections of the same input vector. A token labels itself and decides what it carries.

Routing vs. payload (记住这个区分): Q·K decides who you listen to (the routing). V is what you actually receive (the payload). 全程我们用蓝色表示 Q/K（matchmakers），用橙色表示 V（payload）。

4

Mental Model

Hold this picture in your head:

A sequence is a fully-connected graph of tokens. Attention draws learned, content-dependent weighted edges between them, and recomputes all the edges at every layer. Each token's new representation is a weighted blend of every token's payload (V), where the weights come from query–key match (Q·K).

Three properties fall out of this picture, and they explain almost everything downstream:

  • Parallel: all pairs computed at once → great for GPUs, but it's n × n pairs.
  • Content-dependent: the edges change with the input — that's the power, and why you can't precompute them.
  • Permutation-blind: attention itself has no sense of order — that's why we add positional encoding (Module 03).
5

The Math 技术机制

Plain English first. For each token, score it against every token (dot product), shrink the scores so softmax stays gentle, turn scores into weights that sum to 1, then take a weighted blend of the value vectors. That's it.

The formula:

Attention(Q, K, V) = softmax( Q Kᵀ√dk ) V
SymbolShapeMeaning
Qn × dkQueries — what each of the n tokens is looking for
Kn × dkKeys — what each token advertises
Vn × dvValues — the payload each token carries
QKᵀn × nRaw similarity scores (this is the O(n²) object)
dkscalarKey/query dimension; we scale by its square root
softmaxrow-wiseEach row → weights over keys, summing to 1
outputn × dvEach token's new, context-mixed representation

Implementation meaning: QKᵀ is one matmul, softmax is a row-wise reduction, and the final ×V is another matmul. The whole thing is two matmuls and a softmax — which is exactly why it maps so well onto GPU tensor cores.

Common confusion 常见误区

Softmax is applied per row (over the keys), not over the whole matrix. Each query gets its own probability distribution over the keys. Get the axis wrong and your attention silently becomes nonsense.

Mini exercise · 动手算一下 (reveal answer)

Take Q_sat = [0,1], K_cat = [1,0], K_sat = [0,1], d_k = 2. Compute the two scores, scale by √2, softmax, and say which token "sat" listens to more.

Answer: score(sat→cat) = 0/√2 = 0; score(sat→sat) = 1/√2 ≈ 0.707. softmax([0, 0.707]) ≈ [0.33, 0.67] → "sat" listens 67% to itself, 33% to "cat". The Interactive Lab computes the full matrix live so you can check yourself.

Takeaway: long context is fundamentally a memory problem. FlashAttention keeps the same O(n²) compute but avoids materializing the n×n matrix, so attention memory drops to O(n). That's why it's IO-aware, not a compute trick.

⑤ Training vs. inference — the KV cache

Control: switch mode; in inference, click “Generate next token”. Changes: Q shrinks to a single row; K and V append a cached row each step. Notice: we never recompute past keys/values — we re-read them.

Takeaway: at decode time, compute per token is small but you must load the whole KV cache from HBM every step. That makes autoregressive inference memory-bandwidth bound — the reason for MQA/GQA, PagedAttention (vLLM), and quantized caches.

7

Implementation View

Roughly what the code looks like. Read it after you've played with the pipeline viz — the shapes will map directly onto what you saw.

import numpy as np

def softmax(x, axis=-1):
    x = x - x.max(axis=axis, keepdims=True)   # numerical stability
    e = np.exp(x)
    return e / e.sum(axis=axis, keepdims=True)

def scaled_dot_product_attention(Q, K, V, mask=None):
    # Q: (n, d_k)  K: (n, d_k)  V: (n, d_v)
    d_k = Q.shape[-1]
    scores = Q @ K.T / np.sqrt(d_k)           # (n, n)  <-- the O(n^2) object
    if mask is not None:                      # causal mask: forbid looking ahead
        scores = np.where(mask, scores, -np.inf)
    weights = softmax(scores, axis=-1)        # row-wise: each query sums to 1
    return weights @ V, weights               # (n, d_v), (n, n)
PyTorch one-liner (production path) 
import torch.nn.functional as F
# Fused, FlashAttention-backed when available. Does NOT materialize the n×n matrix.
out = F.scaled_dot_product_attention(q, k, v, is_causal=True)

In real models you'd reshape into heads (batch, heads, n, d_head) and use the fused kernel — that's the bridge to FlashAttention you saw in viz ④.

8

Staff Engineer Lens

🔭 Read this concept like a design review
  • Where is the bottleneck? Training: compute-bound — attention is ~O(n²·d) FLOPs and dominates at long context. Inference decode: memory-bandwidth-bound — you re-read the KV cache every token.
  • What metric reveals the problem? MFU / GPU utilization, tokens/sec, attention memory (GB), KV-cache size (GB), prefill vs decode latency, p50/p99, loss curve, eval score.
  • What breaks at 10× scale? 10× longer context → 100× attention memory (n×n) and 100× prefill FLOPs. KV cache grows linearly with n × layers × heads × d_head → OOM is the first wall you hit.
  • What would a strong engineer ask? “Is this prefill- or decode-bound? What's the batch size and is it continuous batching? Are we paging the KV cache? MQA/GQA? Quantized cache? Is FlashAttention actually being used or did a reshape silently fall back to the slow path?”

The fixes you should be able to name: FlashAttention (IO-aware, O(n) attention memory), MQA/GQA (share K/V across heads → smaller cache), PagedAttention / vLLM (no cache fragmentation), sliding-window / sparse attention (sub-quadratic), and continuous batching (keep the GPU busy across requests).

9

Why this matters for frontier labs

Training

Attention FLOPs dominate long-context pretraining. FlashAttention and sequence parallelism are table stakes; getting the kernel path right is worth millions in compute.

Serving

The KV cache is the inference memory wall. Continuous batching + PagedAttention determine how many users one GPU can serve.

Evaluation

Long-context behavior (needle-in-a-haystack, “lost in the middle”) is an attention story — you measure whether the model actually routes to the right tokens far away.

Reading papers

Attention Is All You Need (2017) → FlashAttention (Dao, 2022) → GQA, sliding-window, linear/sparse attention. This module is the prerequisite for all of them.

Common Confusions

“Attention means the model understands.” No — it computes relevance and routes information. Understanding (if any) lives in the learned weights and the whole stack, not in one softmax.
“If A attends to B, A copies B's embedding.” No — A receives B's Value (payload), scaled by the Q·K weight (routing). Routing ≠ payload. The model can match on one space and transmit another.
“Softmax is over the whole matrix.” No — it's row-wise, over the keys. Each query gets its own distribution that sums to 1.
“Q, K, V are three different inputs.” No — in self-attention they're three learned projections of the same input.
“FlashAttention changes the math / is sub-quadratic compute.” No — same exact output, same O(n²) compute. It changes memory IO by not materializing the n×n matrix.
