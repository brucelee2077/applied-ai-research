The Math, Precisely

You have the recipe. Now read it like an engineer — every shape, every symbol, and the one division that keeps the whole thing trainable.

A volume mixing desk

Picture the desk a sound engineer sits behind at a concert. A row of sliding faders. Each fader controls how loud one source plays — the vocals, the drums, the bass. Push a fader up, that source gets louder in the final mix. Pull it down, it fades into the background.

🎚️
Each fader = one attention weight

It sets how loudly one source plays in the final blend.

🔊
Each source = one Value vector

The actual sound — the payload — that gets mixed in.

🎛️
The master trim = the √dk division

It stops one fader from slamming to maximum and drowning everyone else out.

🔎
Where the desk breaks down

On a real desk a human sets the faders by hand. In attention, the faders are computed from the data on every forward pass — the model decides, fresh each time, how loud each source should be.

One formula, built up piece by piece

Here is the whole operation. We will not read it all at once — we will assemble it left to right, naming every part and its shape as we go.

🧮
The full formula

Attention(Q, K, V) = softmax( Q KT / √dk ) V

Step 1 — the three inputs. Every token in the sequence produces three vectors. Stack them over all n tokens and you get three matrices: matrices Q, K, and V.

Q — n × d_k Queries: what each of the n tokens is looking for. dk is the key/query dimension.
K — n × d_k Keys: what each token advertises. Same width dk as Q, so they can be compared.
V — n × d_v Values: the payload each token carries. Its width dv can differ from dk.

Step 2 — the scores. Multiply Q by K transposed (written KT). This takes the dot product of every query against every key, giving a score for every (query, key) pair.

Q K^T — n × n The raw similarity scores. One number for each of the n × n token pairs. This square is the expensive object — the whole next module is about its cost.

Step 3 — the weights. Divide by √dk, then apply softmax. The softmax runs row-wise: each row is one query, and that row becomes a set of weights over all the keys that sum to exactly 1.

d_k — scalar A single number (for example 64). We divide the scores by its square root before the softmax.
softmax — row-wise Applied per row, over the keys. Each query gets its own distribution that sums to 1. These are the faders on the desk.
output — n × d_v Multiply the weights by V. Each token's new, context-mixed representation. Same width dv as the Values.
💡
Read it as a chain of shapes

(n × dk) · (dk × n) → (n × n) → softmax → (n × n) · (n × dv) → (n × dv). Two matrix multiplies with a row-wise softmax in the middle. That is the entire operation.

The formula as real code

This is the exact function from the lab, reproduced line for line. The shapes in the comments are the same ones you just named. Read the left, then the plain English on the right.

CODE · python 
import numpy as np

def softmax(x, axis=-1):
    x = x - x.max(axis=axis, keepdims=True)   # numerical stability
    e = np.exp(x)
    return e / e.sum(axis=axis, keepdims=True)

def scaled_dot_product_attention(Q, K, V, mask=None):
    # Q: (n, d_k)  K: (n, d_k)  V: (n, d_v)
    d_k = Q.shape[-1]
    scores = Q @ K.T / np.sqrt(d_k)           # (n, n)  <-- the O(n^2) object
    if mask is not None:                      # causal mask: forbid looking ahead
        scores = np.where(mask, scores, -np.inf)
    weights = softmax(scores, axis=-1)        # row-wise: each query sums to 1
    return weights @ V, weights               # (n, d_v), (n, n)
PLAIN ENGLISH

Bring in NumPy, the library for fast math on grids of numbers.

Define softmax — the step that turns scores into faders that sum to 1.

Before taking exponentials, subtract the biggest value in each row. This is numerical stability — it stops the exponentials from overflowing, and it does not change the answer.

Raise e to the power of each (now shifted) score.

Divide each value by the row's total, so the row sums to exactly 1. Those are your weights.

Now the main function: it takes Q, K, V and an optional mask.

A reminder of the shapes: Q and K are n × dk, V is n × dv.

Read dk straight off Q — it is the width of each query vector.

The heart of it: multiply Q by K transposed and divide by √dk. The result is the n × n score grid — the object that costs O(n²).

If a causal mask is given, blank out every future position by setting its score to negative infinity, so it cannot be looked at.

Those blanked scores become exactly 0 after softmax — the model cannot look ahead.

Run softmax along the last axis. That means row-wise: each query becomes its own set of weights over the keys, summing to 1.

Multiply the weights by V to blend the payloads, and hand back both the blend (n × dv) and the weights (n × n).

⚠️
The single most common silent bug

axis=-1 is load-bearing. Softmax over the whole matrix, or over the columns (the queries), still produces numbers that sum to 1 — so nothing crashes — but the attention is now meaningless. The model trains, the loss looks plausible, and the behaviour is quietly wrong.

Why divide by √dk?

This is the master trim on the desk. Without it, one fader slams to the top and silences every other source. With it, the faders stay in a healthy range so the model can still blend several sources together.

Why it happens: a dot product adds up dk products. As dk grows, the scores grow with it — their spread grows like √dk. Feed very large, very spread-out numbers into softmax and it spikes onto a single token: one weight near 1, the rest near 0. A spike like that also flattens the gradient to almost nothing, so the model stops learning. Dividing by √dk cancels that growth and keeps the scores gentle.

🎯
The takeaway in one line

Large dot products make softmax razor-sharp and gradients tiny. Dividing by √dk keeps the scores in a range where the model can still blend multiple sources and still learn.

One failure mode, one trade-off

⚠️

Failure mode: the wrong axis

Run softmax over the whole matrix, or over the columns instead of the rows, and it still sums to 1 — so nothing errors. But each query no longer gets its own distribution over the keys. Attention silently becomes nonsense. Pair this with skipping √dk at large dk: softmax becomes a one-hot spike, the gradient vanishes, and the layer stops learning.

⚖️

Trade-off: the n × n square

Computing Q KT as a full n × n matrix is exact and perfectly parallel — every token pair scored at once, ideal for GPUs. The price is O(n²) memory and compute. Double the sequence length and the square quadruples. That single cost shapes everything about long context — and is exactly the subject of the next module.

💡
Why these two are worth remembering

The wrong-axis bug is the one a senior engineer catches in code review because it never throws an error. The n × n trade-off is the one they raise in a design review, because it decides whether your model can read a whole book or just a paragraph.
