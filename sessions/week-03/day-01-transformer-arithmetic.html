Phase 1 · Week 3 · Day 1 (Mon)

Transformer Arithmetic
C ≈ 6ND

How much does it cost to train a large model? You don't need the source code — you need two numbers. With C ≈ 6ND you can estimate the training compute of GPT-3, or any model, on the back of a napkin. Today: what the formula means and where the 6 comes from.

🎯 By the end, you'll be able to: state the rule C ≈ 6ND, explain why it's 6 (2 forward + 4 backward FLOPs per parameter per token), plug in real numbers for GPT-3, and turn FLOPs into wall-clock time on an H100.
1 · WHAT IS ITWhat is C ≈ 6ND, and why does it exist?✓
🧭
What this assumes: you can multiply big numbers and you know a neural network is made of "weights" (also called parameters). No prior knowledge of FLOP counting needed.

The question: how expensive is it to train a model?

Training a large model can cost millions of dollars and weeks of GPU time. Before you start, you want an estimate: how much compute will this take? Compute is measured in FLOPs — a FLOP is one floating-point operation, meaning a single arithmetic step on decimal numbers, like one multiply or one add. Training a big model takes a huge number of these.

You could try to read all the model code and count every operation. That is slow and error-prone. There is a much simpler way.

The answer: two numbers and a small constant

The total training compute is well approximated by:

🧮
C ≈ 6 × N × D
C = total training compute in FLOPs · N = number of parameters (weights) in the model · D = number of training tokens (pieces of text the model reads during training).

That is the whole thing. If you know how big your model is (N) and how much data you train it on (D), multiply them together, times 6, and you have a solid estimate of the training cost.

What does "per parameter per token" mean?

Here is the key idea. During training, every parameter does a fixed amount of arithmetic for every token the model reads. So the total work grows with parameters times tokens. The 6 is that fixed amount of work — roughly 6 FLOPs each time one parameter meets one token. We'll unpack where the 6 comes from in the next sections.

2 · INTUITIONEvery worker shakes every guest's hand✓

Picture a big party. The workers are the parameters (there are N of them). The guests are the tokens (there are D of them). Training is every worker greeting every guest with a fixed little routine.

🤝
Forward pass = 2 ops

When a worker meets a guest, they do one multiply and one add — that's 2 FLOPs. This is the model making a prediction: weight × input + running total.

🔁
Backward pass = about 4 ops

Then the worker figures out how to improve, which is roughly twice the greeting work — about 4 FLOPs. Learning costs more than predicting.

In one line: each of the N workers greets each of the D guests, doing 2 + 4 = 6 FLOPs each time. Total work = 6 × N × D.

⚠️
Where the analogy breaks: workers don't literally meet guests one at a time. The 6 is an average that folds in the forward and backward passes; the real per-layer math varies, but 6ND is an excellent estimate for the dense parts of a Transformer.

4 · HOW & WHYWhere the 6 comes from, and why the rule holds✓

Breaking down the 6

  • Forward pass = 2 FLOPs per parameter per token. Using a weight means one multiply (weight × input) and one add (into a running sum). That is 2 FLOPs, and it happens once per parameter for each token.
  • Backward pass ≈ 4 FLOPs per parameter per token. Backpropagation — the step that computes how to change each weight — does roughly twice the forward work. It needs one pass to send the error back to the inputs and one to compute the gradient for each weight. That is about 2 × 2 = 4 FLOPs.
  • Add them up: 2 (forward) + 4 (backward) = 6 FLOPs per parameter per token.
✅
C ≈ (2 + 4) × N × D = 6ND
Forward is 2ND. Backward is about 4ND. Training does both for every token, so total training compute is about 6ND.

Why this rule is so useful

  • You only need two numbers. Model size N and token count D are usually the first things you know. No architecture details required.
  • It scales linearly. Double the tokens D and compute doubles. Double the parameters N and compute doubles. This makes budgeting and planning easy.
  • It powers scaling laws. Later work (like Chinchilla) uses 6ND to decide the best split between model size and data for a fixed compute budget.
🔗
Causal chain: each weight does a multiply + add per token (2 FLOPs forward) → backprop roughly doubles that (4 FLOPs backward) → 6 FLOPs per parameter per token → total training compute C ≈ 6ND.
