Phase 1 · Week 3 · Day 2 (Tue)

Q, K, V
Matrix Anatomy

Everyone talks about "attention," but a transformer block is really just a small pile of weight matrices. Today you learn exactly which matrices live inside one block — Wq, Wk, Wv, Wo, and the two feed-forward matrices — and how to count their parameters with one tiny formula.

🎯 By the end, you'll be able to: name the 4 attention matrices and 2 feed-forward matrices, count a block's parameters as roughly 12·d², and scale that to a whole model by multiplying by n_layers.
1 · WHAT IS ITWhat matrices live inside a transformer block?✓
🧭
What this assumes: you can multiply matrices and read shapes like (rows, cols). That's it. No prior transformer knowledge needed. We stay at the shape level — you will not re-derive the attention math today.

A token is just a vector

A transformer works on tokens — small pieces of text, each turned into a list of numbers called a vector. The length of that vector is one number you pick called d_model (often written d). A common value is d = 768. So every token is a vector of 768 numbers.

A block is two sub-parts, made of weight matrices

The model stacks many identical blocks (also called layers). Each block has exactly two sub-parts, and each sub-part is really just a few weight matrices — grids of learned numbers you multiply the token vector by.

Sub-part 1 — Attention. It has 4 matrices, each roughly d × d:

  • Wq (the Query matrix) — reshapes the token to ask "what am I looking for?"
  • Wk (the Key matrix) — reshapes it to say "what do I offer?"
  • Wv (the Value matrix) — reshapes it to say "here is my content."
  • Wo (the Output matrix) — recombines the answer back into a d-long vector.

Sub-part 2 — Feed-forward (FFN, also called MLP). It has 2 matrices: one that goes wide (d × 4d) and one that comes back down (4d × d).

Why this matters: you can count the parameters

A parameter is a single number the model learns. Counting them tells you how big and how expensive a model is. Because the shapes are so regular, the count per block is a tiny formula: 4·d² from attention plus 8·d² from the FFN, which is about 12·d² per block (ignoring small bias terms). Multiply by the number of blocks and you have the whole model's size.

One more detail: multi-head

Multi-head attention splits the d numbers into n_heads smaller groups, each of size head_dim. The only rule you need today: n_heads × head_dim = d_model. The total matrix sizes stay the same, so the parameter count does not change.

2 · INTUITIONThree questions and a funnel✓

Picture one token's vector arriving at a block. Before anything clever happens, the block runs it through matrices that reshape it in different ways.

❓❓❓
Wq, Wk, Wv ask three questions

The same token vector goes into three different matrices. Each asks it a different question: "what do I want?" (Query), "what do I have?" (Key), "what is my content?" (Value). Then Wo recombines the answer back into one vector.

▽
The FFN is a funnel

The feed-forward part first stretches the vector 4× wider (d → 4d), does some work in that wide space, then squeezes it back down (4d → d). Wide-then-narrow.

In one line: a block is 4 attention matrices that reshape and recombine, plus a 2-matrix funnel that expands then contracts — six matrices total.

⚠️
Where the analogy breaks: the matrices are not literally "asking questions." They are just multiplications by learned numbers. "Query / Key / Value" are names for how the results get used later in attention — which you don't need today. Here we only care about their shapes and how many numbers they hold.

4 · HOW & WHYThe counting rules, and why they matter✓

The rules

A matrix of shape (rows, cols) holds rows × cols parameters. Apply that to a block:

  • Attention = 4 matrices, each d × d. Wq, Wk, Wv, Wo. Total: 4 · d².
  • FFN = 2 matrices. Up-projection d × 4d = 4d², down-projection 4d × d = 4d². Total: 8 · d².
  • Per block: 4d² + 8d² = 12 · d² (ignoring small bias vectors, which are only a few thousand numbers).
  • Whole model: multiply by the number of blocks — n_layers · 12 · d².
✅
params_per_block ≈ 12 · d_model²
For d = 768: 12 × 768² ≈ 7.08M parameters per block. Ten blocks ≈ 70M. This is the fast estimate people quote in interviews.

Where multi-head fits

  • Multi-head splits d_model into n_heads groups of head_dim, with n_heads × head_dim = d_model.
  • This changes how the numbers are arranged, not how many there are. The four attention matrices are still d × d in total, so the count stays 4d².

Why this matters

  • Sizing models in your head — "d=768, 12 layers" instantly gives ~85M attention+FFN params, no calculator.
  • Memory and cost — parameters drive training memory, storage, and how much fits on a GPU. d² means doubling d quadruples the cost.
  • FFN dominates — the funnel holds 8d² vs attention's 4d², so two-thirds of a block's weights live in the feed-forward part.
🔗
Causal chain: token = d-vector → each matrix is rows × cols params → 4 attention (4d²) + 2 FFN (8d²) = 12d² per block → × n_layers = model size.

Acceptance criteria
