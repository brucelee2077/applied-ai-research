Module 5a · Represent · Day 8

The Tower of
Identical Floors

The module finale. You have every piece: the block, the mask, the way to pick a word. Today you stack them into a whole decoder-only transformer. Words go in at the bottom, become numbers, ride up through N identical floors, and a final projection turns the top floor's numbers back into a next-word guess. This is the exact shape of GPT — just smaller.

🎯 By the end, you'll be able to: assemble a full decoder-only transformer — token + positional embeddings → N stacked blocks → final linear head → next-token logits — and explain how it generates text.
1 · WHAT IS ITBottom, middle, top — the whole model✓
🧭
What this assumes: you have the decoder block (Day 4), causal masking (Day 5), and generation (Day 7), plus embeddings and positional encoding from M3.

The bottom: turn words into numbers

A word cannot go into math directly. First, a token embedding looks up a learned list of numbers for each token. Then a positional embedding is added so the model knows the order of the words. Attention on its own has no sense of "first" or "third", so this order signal matters.

The middle: N stacked blocks

The token-plus-position numbers ride up through N copies of the decoder block from Day 4 — each with the causal mask. Every block keeps the same shape, so they stack cleanly. This is where nearly all the model's thinking happens.

The top: turn numbers back into a word

At the top, a final linear head (also called the output projection or the unembedding) turns the top block's numbers into one score — a logit — for every word in the vocabulary. Softmax then gives probabilities, and you pick the next word (Day 7).

🧮
tokens → embed + position → block ×N → linear head → next-word logits

That is a complete decoder-only transformer. Keep going 👇

2 · INTUITIONA tower of identical floors✓
🏢
Enter on the ground floor

Words walk in the front door and get name tags (embeddings) plus a note of where they stand in line (position). Then they take the elevator up.

🏗️
Every floor is the same

Each floor is one decoder block: meet (attention), then think (feed-forward). The floors look identical, but each has its own learned staff. On the roof, a final desk hands each token a next-word guess.

In one line: a transformer is a tower — names and positions at the bottom, a stack of identical thinking floors in the middle, and a next-word desk on the roof.

🎮
Your toy tower might have 2 floors and tiny rooms. GPT-3 has 96 floors and huge rooms. Same building design, wildly different size. That is the whole story of scale.
⚠️
Where the analogy breaks: in a real building each floor is separate, but here the tokens flow through all floors as one continuous set of numbers, and the residual highways (Day 1) mean the ground-floor signal is still present at the roof.

4 · MECHANISM & WHYThe full forward pass, shape by shape✓

Step 1 — in plain words

Take the token ids. Look up an embedding for each and add its position. Send the result up through N decoder blocks, each with the causal mask. Take the top output and multiply by the head to get one score per vocabulary word. Softmax and pick — that is one generated token. Loop to get more.

Step 2 — the forward pass, symbol by symbol

🧮
x = token_embed[ids] + pos_embed # (seq_len, d_model)
for block in blocks: # N decoder blocks
    x = block(x, causal_mask) # stays (seq_len, d_model)
logits = x @ W_head # (seq_len, vocab_size)
ids = the input token ids
W_head = the final linear head, (d_model, vocab_size)
logits = a score per word, at every position

Step 3 — a worked example with small numbers

Say vocab_size = 8, d_model = 16, N = 2 blocks, and a prompt of 2 tokens.

  • Embed + position → shape (2, 16).
  • Block 1 → (2, 16); Block 2 → (2, 16). Shape never changes.
  • Head (16, 8): (2, 16) @ (16, 8) → (2, 8). That is 8 scores (one per vocab word) at each position.
  • Take the last position's 8 scores → softmax → pick the next word (Day 7).

Why it matters — you built the frontier's shape

🔗
The big picture: this is the real architecture of a decoder-only LLM. Your toy has maybe a thousand parameters; GPT-4 has trillions. Same embeddings, same stacked blocks, same causal mask, same head. The only differences are size and training data. You now understand, end to end, how a large language model turns text into text.

The staff lens — one silent failure, one trade-off

Assembling the full model means one line adds position and one pair of big matrices bookends the stack — and both are places where a quiet mistake or a quiet saving lives.

⚠️
Failure mode (silent): forgetting to add the positional embedding. Attention has no built-in sense of order — it treats the tokens as an unordered bag. The + pos_embed line is what tells the model where each token sits. If you drop it, every shape still matches and the model still trains and produces fluent-looking text, but it cannot tell "dog bites man" from "man bites dog" because word order carries no signal. There is no crash — just a quality ceiling you cannot explain. A senior engineer in code review confirms position information is actually added (or a positional scheme like RoPE is applied inside attention), because a transformer with no positions fails silently, not loudly.
⚖️
Trade-off: weight tying saves parameters but couples two jobs. The input token embedding and the output head are both vocab_size × d_model matrices, so for a large vocabulary they can dominate the parameter count. Tying them — using the same matrix for "id → vector" and "vector → word score" — cuts that cost roughly in half and often helps small models. The price is that one matrix must now serve both the input and output roles, which can slightly limit a very large model. In a design review weight tying is the classic choice: worth it to shrink smaller models, sometimes dropped when you have parameters to spare.
