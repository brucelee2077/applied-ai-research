Phase 4 · Week 15 · Day 3 (Wed)

Extreme Compression
(QuIP#)

A 16-bit LLM weight is one of 65,536 possible values. Squeeze it to 2 bits — only ~4 states — and naive rounding makes the model collapse to gibberish. Today: how QuIP, QuIP#, QTIP, and AQLM squeeze weights to ~2 bits and keep the model working, using incoherence, lattices, and trellises.

🎯 By the end, you'll be able to: explain why 2-bit round-to-nearest collapses an LLM, how incoherence processing (the Hadamard transform) flattens outliers, why the E₈ lattice beats scalar rounding at the same bitrate, and how QTIP's trellis and AQLM's sum-of-codebooks push even further.
1 · WHAT IS ITWhat is 2-bit post-training quantization?✓
🧭
What this assumes: you know a neural network layer is a big matrix of numbers (weights), and that a matrix multiply turns inputs into outputs. That is all. No prior quantization experience needed.

First, the words

A trained model stores each weight as a 16-bit float: a number picked from 65,536 possible values. Quantization means replacing those high-precision numbers with a small set of low-precision codes to shrink memory. "2-bit" means each weight is stored using only 2 bits on average — so instead of 65,536 choices, each number effectively picks from about 4 states. That is roughly an 8× memory cut.

Post-training quantization (PTQ) means you compress an already-trained model without retraining it from scratch. You only look at the weights, plus a small calibration dataset (a few example inputs), and never run full training again.

Why do we even want this?

Serving an LLM is memory-bound: the slow part is moving billions of weights from memory to the compute units. Fewer bits per weight means the whole model fits in less memory, more of it fits on one GPU, and each token is generated faster. That is the prize.

The problem that makes today hard

At 2 bits, the obvious idea — round each weight to the nearest of 4 levels (called round-to-nearest, RTN) — destroys the model. The errors are large and they line up in bad ways, so accuracy collapses and perplexity (a "how confused is the model" score, lower is better) explodes to huge numbers or NaN.

Chris De Sa's group (QuIP, QuIP#, QTIP at Cornell) built most of the fix, with four building blocks that are the whole lesson: (1) measure error the right way (the Hessian proxy loss), (2) incoherence processing to flatten outliers, (3) lattice codebooks (the E₈ lattice) to round groups of weights together, and (4) ways to beat the codebook-size wall — QTIP's trellis coding and, from a separate group (Egiazarian, Alistarh et al.), AQLM's additive codebooks.

📚
Official papers (optional): QuIP · QuIP# · QTIP · AQLM — Additive Quantization of Language Models
2 · INTUITIONShipping a huge library in tiny boxes✓

Imagine you must ship a huge library overseas in tiny boxes. Each book is a weight. The box size is your bit budget — and today the budget is very small (2 bits).

📚➡️📦
Naive 2-bit rounding = 4 fixed thicknesses

You are told "every book must be squashed to one of 4 standard thicknesses." Thick reference books and thin pamphlets both get mangled. The fit is terrible — this is RTN collapse.

✂️📖
Incoherence = re-cut books to one size first

The Hadamard transform re-cuts every book to nearly the same size before boxing. No monster volume forces oversized boxes on everyone, so a coarse set of box sizes now fits all books well.

🧊🧊
Lattice codebooks (E₈) = pack in tight groups of 8

Instead of one book per box, pack books in groups of 8 using the tightest known arrangement in 8 dimensions. The empty space between books shrinks — same content, fewer bits.

🏷️➕🔢
Trellis (QTIP) = compute each label from the last

Instead of writing a full unique address on every crate, each crate's label is computed from the previous crate's label plus a couple of digits. You describe enormous packing patterns with a tiny lookup rule.

In one line: flatten the outliers, pack weights in tight groups, and describe the packing with a tiny stateful rule — that is how you hit 2 bits without breaking the model.

⚠️
Where the analogy breaks: books are independent, but weights interact through the activation Hessian. The cost of squashing one weight depends on which other weights it sits near in the computation, so the real objective is correlated error tr(ΔW·H·ΔWᵀ), not per-book thickness. Physical packing has no such coupling.

4 · HOW & WHYThe four building blocks, and why each is needed✓

The four building blocks

  • (1) Measure error correctly. When you round weight W to Ŵ, the error is ΔW = Ŵ − W. What matters is not ‖ΔW‖ itself but how that error interacts with the layer's inputs, captured by the Hessian H = E[xxᵀ] (from calibration activations x). The real objective is tr(ΔW·H·ΔWᵀ): errors aligned with high-variance input directions hurt most.
  • (2) Incoherence processing. A matrix is incoherent when no single entry is huge relative to the rest — no outliers. QuIP multiplies W' = U·W·Vᵀ with random orthogonal matrices (undone at inference). QuIP# uses the Randomized Hadamard Transform (a ±1 matrix with a fast O(n log n) transform), so it is nearly free at runtime and flattens outliers into a smooth sub-Gaussian ball.
  • (3) Vector quantization on a lattice. Instead of rounding one weight at a time, round a group of d weights together to the nearest point in a fixed codebook. A lattice is a regular repeating grid; QuIP# uses the E₈ lattice — the optimal packing of balls in 8 dimensions — for less error per bit. QuIP# then briefly fine-tunes to match the original outputs.
  • (4) Beat the codebook wall. A VQ codebook has size 2^(bits·d), so it caps out near d≈8. QTIP uses trellis coded quantization: a stateful decoder generates values from the current state plus incoming bits, separating stored bits from effective dimension. AQLM takes a different route: represent each group as a sum of vectors Ŵ = c₁ + c₂ + … from several small codebooks, giving Kᴹ combinations from M·log₂K bits.
✅
minimize tr(ΔW·H·ΔWᵀ)  — not  minimize ‖ΔW‖
"Penalize error along the input directions the layer actually uses." This is what greedy/adaptive rounding (QuIP's LDLQ) targets — direction matters, not raw magnitude.

Why this chain works

  • Incoherence first — a smooth ball-shaped distribution lets a uniform grid cover every weight well, so no outlier forces a coarse grid on everyone.
  • Lattices beat scalars — packing groups of weights with the tightest arrangement shrinks the quantization cells, so error per bit drops.
  • Trellis/additive beat the wall — decoupling stored bits from dimension (QTIP) or summing codebooks (AQLM) reaches ultra-rich representations at ~2 bits with tiny stored tables.
🔗
Causal chain: memory-bound inference → want ~2 bits → naive RTN collapses (outliers + wrong error metric) → incoherence flattens outliers → lattice VQ shrinks cells → fine-tune closes the gap → trellis/additive push past the codebook wall.

⚠️
Gotcha: the common mistake is minimizing the wrong error — ‖ΔW‖ ignores that weights interact through H = E[xxᵀ]. Two quantizations with equal ‖ΔW‖ can give wildly different output error.
