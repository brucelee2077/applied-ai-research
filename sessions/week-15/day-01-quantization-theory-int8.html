Quantization Theory
(int8)

A big model stores every weight as a 16-bit float. Swap those for 8-bit integers and you cut memory roughly in half — the model that needed two GPUs now fits on one. But do it the naive way and a large model silently loses its accuracy. Today: how int8 quantization works, why it breaks, and the clever fix that made it safe.

🎯 By the end, you'll be able to: explain absmax int8 quantization and its scale factor, describe why a single outlier feature destroys accuracy in large transformers, and describe how LLM.int8() mixed-precision decomposition fixes it.
1 · WHAT IS ITWhat is quantization, and what is int8?✓
🧭
What this assumes: you know a neural network is a big pile of numbers (the weights) that get multiplied together, and that these live on a GPU with limited memory. No prior knowledge of number formats needed — we start from zero.

First, the vocabulary

A number inside a neural network is normally stored as a float (short for "floating point"). The most common kind is FP16: 16 bits (a bit is a single 0 or 1) per number. FP16 can represent a huge range of values, including fractions like 0.0037 or 128.5.

Quantization means one thing: replace those 16-bit floats with smaller numbers, most often INT8 — 8-bit signed integers, meaning whole numbers from -127 to +127. Fewer bits means two wins: the model takes less memory to store, and the multiply hardware is cheaper and faster. So the model runs faster and fits on smaller GPUs.

The catch: 256 seats vs. tens of thousands

An INT8 can hold only 256 distinct values. FP16 can hold tens of thousands. To squeeze floats onto that tiny grid, you pick a scale factor called s. You find the largest absolute value in a group of numbers (the absmax), set s = absmax / 127, store each number as round(x / s), and recover it later as int_value × s. This is absmax quantization.

Because the scale is set by the biggest value, one huge number stretches the grid and squashes all the small numbers toward zero — they lose their detail. That lost detail is called quantization error.

The discovery: outlier features

In large transformers, a few specific feature dimensions (columns of the hidden-state matrix — the vector of numbers flowing between layers) grow enormously larger than the rest, sometimes about 20× larger. These are outlier features. They are not random: past a size threshold (around 6.7 billion parameters) they appear in the same handful of dimensions (up to ~7 of them) across almost every token and layer, and the model relies on them heavily. When you absmax-quantize a whole vector containing one of these giants, every ordinary feature gets crushed into a couple of buckets and accuracy collapses. This is catastrophic degradation.

The fix: LLM.int8()

LLM.int8() uses mixed-precision decomposition. It splits each matrix multiply into two parts: the few outlier dimensions stay in FP16 and are multiplied in FP16, while the ~99.9% of ordinary dimensions are quantized to INT8. The two partial results are added back together. Because the outliers never enter the INT8 path, they never stretch the INT8 grid — so ordinary features keep their precision. The result: 8-bit inference with essentially zero accuracy loss, even at 175B parameters.

📚
Official docs (optional): LLM.int8() paper (Dettmers et al.) · bitsandbytes on GitHub
2 · INTUITIONThe bus with 256 numbered seats✓

Think of quantization as fitting a room full of people onto a bus with only 256 numbered seats, where a person's seat number must be proportional to their height. You measure the tallest person and give them seat 127. Everyone else gets seat = round(their_height / tallest_height × 127).

🧍🧍🧍
Normal adults → clean seating

If everyone is a normal-height adult, heights spread nicely across the seats. A 5-foot person and a 6-foot person land in clearly different seats. You can still tell everyone apart.

🦒
One 30-foot giant → chaos

Now one passenger is a 30-foot circus giant. To fit him in seat 127, the scale stretches so much that every normal adult rounds to the same few low seat numbers. You can no longer tell them apart.

That lost distinction is the accuracy collapse. The giant is the outlier feature; the normal adults are the ordinary features that got crushed.

LLM.int8()'s trick: put the giant on his own private FP16 minibus, and seat only the normal-height people on the INT8 bus — where they now spread out beautifully across all 256 seats.

⚠️
Where the analogy breaks: real outlier features are not one lone giant but a small fixed set of dimensions (about 7) that are systematically large across nearly all tokens. They are a structural property of the network, not a rare visitor — which is exactly why you can reliably detect and route them.

4 · HOW & WHYThe rules of int8 quantization, and why it matters✓

The rules

  • absmax int8: find absmax = max(|x|) of a group, set s = absmax / 127, store q = round(x / s) as an integer in [-127, 127], recover with x̂ = q × s.
  • The scale is set by the biggest value. So one giant value makes s large, and every small value rounds to the same few integers. That is where accuracy dies.
  • Weights vs. activations are different. Weights are static and well-behaved — per-tensor absmax int8 on weights is fine. The outlier problem lives in the activations (the runtime hidden states), which is why outliers are detected per input at inference time, not once at load.
  • Mixed-precision decomposition (LLM.int8): detect outlier columns (|x| > threshold), run those in FP16, run the rest in INT8, and add the two partial matmuls together.
✅
result = (X_int8 @ W_int8) · s  +  (X_outlier_fp16 @ W_outlier_fp16)
"Multiply the ~99.9% ordinary columns in cheap INT8, multiply the ~7 outlier columns in FP16, then sum. Outliers never touch the INT8 grid, so ordinary features stay sharp."

Why it matters

  • Half the memory — 8 bits instead of 16 means a model that needed two GPUs can fit on one. Same idea that lets you serve bigger models on cheaper hardware.
  • Essentially no accuracy loss — plain int8 collapses above ~6.7B params; LLM.int8() keeps full accuracy even at 175B, because it never lets an outlier stretch the grid.
  • The trade is bookkeeping — you pay a little extra work finding outlier columns at runtime and keeping a thin FP16 side-path, in exchange for roughly halving memory.
🔗
Causal chain: INT8 has only 256 buckets → the scale is set by the absmax → a systematic outlier feature stretches the scale → ordinary features get crushed → accuracy collapses → route outliers to FP16 so the INT8 grid resolves the rest cleanly.
