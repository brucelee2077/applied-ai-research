Quantization: fp16 → int8 → 2-bit & Outlier Features

Quantization means storing model numbers with fewer bits (16 → 8 → 4 → 2) to shrink memory and speed up inference. Fewer bits = less memory, but a few huge "outlier" values can wreck a naive scheme. Play with the two figures below to see the memory win — and why isolating or rotating outliers is what makes extreme low-bit quantization actually work.

🎯 What to notice

  • Lower bits = linearly less memory. int8 halves fp16; int4 is 4× smaller; 2-bit is 8×. Inference is usually memory-bandwidth-bound, so smaller weights also mean faster token generation.
  • A few outlier features cause catastrophic error. One giant value forces a coarse scale, so all the small values collapse toward 0. Crank the outlier magnitude with "Naive int8" and watch the error explode.
  • Isolate or rotate the outliers. LLM.int8() keeps outlier columns in fp16 and int8s the rest — error stays tiny. QuIP multiplies by a random orthogonal (Hadamard) matrix to spread the outlier energy so no single value dominates (incoherence max/RMS drops toward 1), which is what enables coherent 2-bit quantization. The rotation win grows with dimension — real QuIP rotates whole weight matrices with per-block scales and lattice codebooks, so a 16-wide toy only hints at it.
