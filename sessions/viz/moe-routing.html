Mixture-of-Experts: Token Routing & Load Balancing

← All lessons

A Mixture-of-Experts (MoE) layer holds many small feed-forward networks called experts. A tiny gating network reads each token and sends it to only the top-k experts instead of all of them — so the model has huge total parameters but runs cheap per token. What to notice

  • Sparse compute, dense knowledge. Each token only touches top_k / E of the experts, so compute stays flat while total parameters can grow enormous. That is the whole selling point of MoE.
  • Skew causes drops. Slide routing skew up: a few experts overflow their capacity ceil(cf · top_k · n / E) and the extra tokens turn red — dropped. Dropped tokens get no expert output, which hurts quality.
  • Why the aux loss & capacity factor exist. An auxiliary load-balancing loss pushes the imbalance ratio toward 1.0 (uniform), and a larger capacity factor adds buffer so fewer tokens drop — at the cost of more memory and padding.
