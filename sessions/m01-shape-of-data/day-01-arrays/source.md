  <div class="sec-head"><span class="sec-num s-what">1</span><span class="sec-h"><span class="lang-en">First, what is an array — and what is NumPy?</span><span class="lang-zh">先说清楚：array 是什么？NumPy 又是什么？</span></span><span class="sec-tag"><span class="lang-en">What is it</span><span class="lang-zh">这是什么</span></span></div>

      <div class="callout c-info"><span class="ic">🧭</span><div><span class="lang-en"><b>What this assumes:</b> a little Python — you know a variable, a <code>list</code> like <code>[1, 2, 3]</code>, and a <code>for</code> loop. <b>No math or NumPy background needed</b> — we start from zero.</span><span class="lang-zh"><b>这一天假设你已经会：</b>一点点 Python —— 你知道什么是变量，见过 <code>[1, 2, 3]</code> 这样的 <code>list</code>，也写过 <code>for</code> 循环。<b>数学和 NumPy 都不需要底子</b> —— 我们从零开始。</span></div></div>

      <h4><span class="lang-en">What is NumPy?</span><span class="lang-zh">NumPy 是什么？</span></h4>
      <p><span class="lang-en"><span class="term" data-tip="A Python library for fast math on whole arrays of numbers at once. Imported as np.">NumPy</span> is a Python library for doing math on big collections of numbers <strong>quickly</strong>. It is the foundation almost every other data and machine-learning tool is built on. By convention you import it and call it <code>np</code>:</span><span class="lang-zh"><span class="term" data-tip="一个 Python 库，能一次对一整个 array 的数字做很快的数学。导入以后叫它 np。">NumPy</span> 是一个 Python 库，用来对一大堆数字<strong>很快地</strong>做数学。差不多所有别的数据工具和机器学习工具，都是搭在它上面的。大家习惯这样导入它，并且叫它 <code>np</code>：</span></p>
      <div class="callout c-info"><span class="ic">📦</span><div><code>import numpy as np</code><br><span style="font-size:.85rem;color:var(--text2)"><span class="lang-en">From now on, <code>np.something(...)</code> means "use NumPy's version of something."</span><span class="lang-zh">从现在起，<code>np.something(...)</code> 的意思就是「用 NumPy 那个版本的东西」。</span></span></div></div>

      <h4><span class="lang-en">What is an array?</span><span class="lang-zh">array 是什么？</span></h4>
      <p><span class="lang-en">An <span class="term" data-tip="An ordered grid of numbers, all the same type, stored together in memory.">array</span> is an <strong>ordered grid of numbers</strong>, all of the same type, stored together. You make one from a plain list:</span><span class="lang-zh">一个 <span class="term" data-tip="一格一格排好的数字，类型全都一样，挨在一起存在内存里。">array</span> 就是<strong>排好顺序的一格一格数字</strong>。它们的类型全都一样，而且挨在一起存着。你用一个普通的 list 就能做出一个：</span></p>
      <div class="callout c-info"><span class="ic">🔢</span><div><code>x = np.array([1, 2, 3])</code><br><span style="font-size:.85rem;color:var(--text2)"><span class="lang-en">This turns a Python list into a NumPy array — a tidy row of three numbers.</span><span class="lang-zh">这行把一个 Python list 变成了 NumPy array —— 整整齐齐的一排三个数字。</span></span></div></div>

      <h4><span class="lang-en">How is that different from a Python list?</span><span class="lang-zh">它跟 Python list 有什么不一样？</span></h4>
      <p><span class="lang-en">A Python list is a loose bag: it can hold anything (numbers, text, other lists), in any mix, and to do math you have to loop over it item by item. An array is stricter and, because of that, far faster: <strong>one type, one regular grid</strong> — so the computer can crunch every number at once.</span><span class="lang-zh">Python list 像一个松松的袋子。里面什么都能装：数字、文字、别的 list，混着装也行。想做数学，你只能一个一个循环过去。array 更严格。正因为严格，它快得多：<strong>一种类型，一张整齐的格子</strong>。这样电脑就能一次把每个数字都算完。</span></p>
      <p><span class="lang-en">The single most important thing about an array is its <span class="term" data-tip="A tuple giving the size of an array along each dimension, e.g. (2, 3) = 2 rows, 3 columns.">shape</span> — the sizes of its grid. That is today's puzzle. Keep going 👇</span><span class="lang-zh">array 身上最重要的一件事，是它的 <span class="term" data-tip="一个 tuple，说出 array 在每个方向上有多大，比如 (2, 3) = 2 行 3 列。">shape</span> —— 也就是这张格子有多大。这就是今天的谜题。继续往下 👇</span></p>
      <div class="callout c-info"><span class="ic">🏭</span><div><span class="lang-en"><b>A real one:</b> GPT-3's biggest weight matrix is a rigid grid of shape <code>(12288, 49152)</code> — over 600 million numbers, one matrix, inside one model. Shape is not a toy idea.</span><span class="lang-zh"><b>真实的例子：</b>GPT-3 里最大的那个 weight matrix（矩阵），是一张死板板的格子，shape 是 <code>(12288, 49152)</code>。那是六亿多个数字，装在一个 matrix 里，藏在一个 model（模型）里面。shape 不是课堂上的玩具。</span></div></div>
      <div class="callout c-warn"><span class="ic">😕</span><div><span class="lang-en"><b>Why this trips people up:</b> "array" sounds like just another name for a Python list, so people skip shape and go straight to writing code. In plain terms: people treat an array as "just a fast list" and never learn to read its <code>shape</code> — then every later bug (a matmul that won't line up, a batch axis in the wrong place) is really a shape they never learned to see.</span><span class="lang-zh"><b>为什么这里容易卡住：</b>「array」听起来只是 Python list 的另一个名字，于是很多人跳过 shape，直接开始写代码。说白了：他们把 array 当成「一个跑得快的 list」，从来没学会读它的 <code>shape</code>。后面每一个 bug 都是这么来的：matmul（矩阵乘法）对不上，batch 的 axis（轴）放错了地方。追到底，都是一个他们从没学会看的 shape。</span></div></div>

<section class="module-section" id="s4" data-sec="why">
  <div class="sec-head"><span class="sec-num s-study">4</span><span class="sec-h"><span class="lang-en">The three facts every array carries — and why labs live in them</span><span class="lang-zh">每个 array 都带着的三件事 —— 以及实验室为什么天天泡在里面</span></span><span class="sec-tag"><span class="lang-en">Mechanism &amp; why</span><span class="lang-zh">原理和为什么</span></span></div>
  <div class="sec-body">
      <h4><span class="lang-en">Every array has three labels</span><span class="lang-zh">每个 array 都有三个标签</span></h4>
      <ul>
        <li><span class="lang-en"><strong><span class="term" data-tip="The single data type every element of an array shares, e.g. int32 or float32.">dtype</span></strong> — the one type every element shares (e.g. <code>int32</code>, <code>float32</code>). No mixing.</span><span class="lang-zh"><strong><span class="term" data-tip="array 里每个元素共用的那一种数据类型，比如 int32 或者 float32。">dtype</span></strong> —— 每个元素共用的那一种类型（比如 <code>int32</code>、<code>float32</code>）。不能混着放。</span></li>
        <li><span class="lang-en"><strong>shape</strong> — a tuple of the sizes along each dimension: <code>(2, 3)</code> = 2 rows, 3 columns.</span><span class="lang-zh"><strong>shape</strong> —— 一个 tuple（元组），说出每个 dimension 上有多大：<code>(2, 3)</code> = 2 行 3 列。</span></li>
        <li><span class="lang-en"><strong><code>ndim</code></strong> — how many dimensions there are (the length of the shape tuple).</span><span class="lang-zh"><strong><code>ndim</code></strong> —— 一共有几个 dimension（也就是 shape 这个 tuple 的长度）。</span></li>
      </ul>

      <h4><span class="lang-en">Why the rigid grid is a superpower</span><span class="lang-zh">死板的格子为什么是一种超能力</span></h4>
      <p><span class="lang-en">Because every element is the same type and packed together, the computer can do one instruction on <strong>many numbers at once</strong> — this is <span class="term" data-tip="Doing one operation on every element of an array at once, in fast compiled code, instead of a Python loop.">vectorization</span>. <code>x + 10</code> adds 10 to a million numbers with no Python loop, running in fast compiled code.</span><span class="lang-zh">因为每个元素类型都一样，还挨在一起挤着放，电脑就能用一条指令<strong>一次算很多个数字</strong>。这件事叫 <span class="term" data-tip="一次对 array 的每个元素做同一个运算，跑的是编译好的快代码，不是 Python 循环。">vectorization</span>。<code>x + 10</code> 给一百万个数字都加上 10，一个 Python 循环都不用，跑的是编译好的快代码。</span></p>
      <div class="callout c-info"><span class="ic">🔗</span><div><span class="lang-en"><b>Remember this causal chain:</b> same type + regular grid → packed together in memory → one instruction touches many numbers → fast math → training big models becomes possible. <strong>No grid, no speed.</strong></span><span class="lang-zh"><b>把这条因果链记住：</b>类型一样 + 格子整齐 → 在内存里挨着放 → 一条指令碰到很多个数字 → 数学算得快 → 训练大 model 才变得可能。<strong>没有格子，就没有速度。</strong></span></div></div>

      <h4><span class="lang-en">Why a frontier lab cares</span><span class="lang-zh">前沿实验室为什么在意这件事</span></h4>
      <p><span class="lang-en">That same <code>(12288, 49152)</code> matrix from the top of this page does not sit alone. It lives inside one of GPT-3's 96 layers, each layer 12,288 numbers wide. A handful of matrices like it repeat in every one of those 96 layers. Every weight, every batch of tokens, every image inside a model is an array (a <span class="term" data-tip="The general word for an array with any number of dimensions (3-D, 4-D, ...). Used everywhere in ML.">tensor</span>). The number-one bug in machine-learning code is a <strong>shape mismatch</strong> — two arrays that don't line up. Reading shapes fluently is the skill that everything later (attention, batching, scaling) is built on. That is why Day 1 is arrays.</span><span class="lang-zh">这一页最上面那个 <code>(12288, 49152)</code> 的 matrix，不是孤零零地待着。它住在 GPT-3 的 96 层里的某一层，每一层宽 12,288 个数字。像它这样的几个 matrix，在那 96 层里每一层都要再来一遍。一个 model 里的每个 weight、每一批 token（词元）、每一张图片，都是一个 array，也就是一个 <span class="term" data-tip="不管有几个 dimension（3-D、4-D……）的 array，都可以叫它。机器学习里到处都是这个词。">tensor（张量）</span>。机器学习代码里最常见的 bug，就是 <strong>shape 对不上</strong> —— 两个 array 没对齐。把 shape 读得顺，是后面所有东西站着的地基，包括 attention（注意力）、batch 和 scaling。这就是第 1 天讲 array 的原因。</span></p>
      <div class="callout c-warn"><span class="ic">⚠️</span><div><span class="lang-en"><b>Staff / Research Engineer Lens — the silent failure:</b> a shape bug rarely crashes. NumPy will happily broadcast a <code>(32,)</code> against a <code>(32, 1)</code> and hand you a <code>(32, 32)</code> — training keeps running, the loss looks plausible, and you ship a model that learned the wrong thing. <b>⚖️ Trade-off in code review:</b> a one-line <code>assert x.shape == (B, T, C)</code> at each boundary costs nothing and kills the class of bug that otherwise eats an afternoon of debugging.</span><span class="lang-zh"><b>Staff / 研究工程师视角 —— 不出声的失败：</b>shape 出错，很少会让程序崩掉。NumPy 会很乐意把一个 <code>(32,)</code> 和一个 <code>(32, 1)</code> 做 broadcasting（广播），然后递给你一个 <code>(32, 32)</code>。训练照样在跑，loss（损失）看着也像那么回事，可你交出去的 model 学的是错的东西。<b>⚖️ 代码评审里的取舍：</b>在每个交接的地方写一行 <code>assert x.shape == (B, T, C)</code>，几乎不花代价，却能干掉这一整类 bug。不写，它能吃掉你一下午。</span></div></div>
      <div class="callout c-ok"><span class="ic">🎤</span><div><span class="lang-en"><b>Say this in an interview:</b> "An array is a dtype plus a shape over one contiguous block of memory — that is what makes it vectorizable: one instruction over the whole grid. The nuance is that the costliest bugs in ML code aren't crashes, they're silent shape mismatches that broadcast into a wrong-but-plausible result, so I annotate expected shapes at every boundary."</span><span class="lang-zh"><b>面试时可以这样说：</b>「一个 array 就是一个 dtype 加一个 shape，铺在一整块连着的内存上。正因为这样，它才能被 vectorize：一条指令扫完整张格子。再细一点说，ML 代码里最贵的 bug 不是崩掉，而是不出声的 shape 对不上。它会 broadcast 成一个错的、但看着挺合理的结果。所以我在每个交接的地方，都把预期的 shape 写出来。」</span></div></div>
