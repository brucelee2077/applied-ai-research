Indexing & Slicingindex（索引）与 slice（切片）Grab Any Piece of an Array把 array（数组）里任何一块拿出来

Yesterday you built arrays and read their shape. Today you learn to reach in and pull out exactly the piece you want — one number, a range, a whole row, a whole column. This is how every model grabs a batch, a token range, or one attention head.昨天你做出了 array，也读懂了它的 shape（形状）。今天你要学着伸手进去，把你想要的那一块正好拿出来。可以是一个数字。可以是一段范围。可以是一整行，也可以是一整列。每个 model 抓一个 batch、一段 token、或者一个 attention head，用的都是这一招。

By the end, you'll be able to: pull a single element, a slice, and a full row or column out of a 2-D array — and explain why the stop in a:b is left out.学完这一天，你能做到：从一个 2-D array 里拿出单个元素、一个 slice、一整行或者一整列。你还能说清楚 a:b 里的 stop 为什么不算进去。
1Indexing vs. slicing — what each one doesindex 和 slice —— 各自做什么What is it这是什么
🧭
What this assumes: Day 1 — you can make an array and read its shape. No new tools today — just two ways of reaching into an array.这一天假设你已经会：第 1 天的东西 —— 你能做出一个 array，也能读出它的 shape。今天没有新工具 —— 只有两种伸手进 array 的方法。

What is indexing?什么是 indexing？

Indexing means grabbing one element by its position. Positions count from 0, exactly like a Python list: x[0] is the first element, x[2] the third.indexing 的意思是按位置拿一个元素。位置从 0 开始数，跟 Python list 完全一样。x[0] 是第一个元素，x[2] 是第三个。

What is slicing?什么是 slicing？

Slicing means grabbing a range with start:stop. The catch you must remember forever: the stop is excluded. x[1:3] gives positions 1 and 2 — not 3.slicing 的意思是用 start:stop 拿一段范围。有一个坑你要记一辈子：stop 不算在里面。x[1:3] 给你位置 1 和位置 2 —— 没有 3。

How does it relate to what you know?它跟你已经会的东西有什么关系？

This is the same x[0] and x[1:3] you already use on Python lists. Arrays add one new move: for a grid you separate the dimensions with a comma — g[row, col]. And a lone colon : means "everything on this axis."这就是你在 Python list 上早就用过的 x[0] 和 x[1:3]。array 只多了一个新动作。面对一张网格，你用逗号把 dimension（维度）分开 —— g[row, col]。单独一个冒号 : 的意思是「这条 axis（轴） 上全都要」。

Two symbols do all the work today: the comma (separate axes) and the colon (a range, or "all"). Keep going 👇今天的活全靠两个符号干完：逗号（分开 axis）和冒号（一段范围，或者「全都要」）。继续往下 👇

🏭
A real one: vLLM, one of the most-used serving engines for LLMs, is built around PagedAttention — it slices the KV cache into fixed-size blocks the exact same way an operating system pages memory. Slicing isn't just a classroom trick.真实的例子：vLLM 是给 LLM 提供服务最常用的引擎之一，它的核心是 PagedAttention。它把 KV cache 切成一块块固定大小的 block。这个做法跟操作系统给内存分页完全一样。slicing 不是课堂上的小把戏。
😕
Why this trips people up: x[1:3] looks like it reaches 3, but it does not — the half-open rule feels arbitrary until it burns you. In plain terms: people read start:stop as inclusive, so their batch is one row short (or one too many), and the off-by-one hides for hours because nothing crashes.为什么这里容易卡住：x[1:3] 看起来能取到 3，其实取不到。half-open（半开区间）这个规矩一开始会让人觉得没道理，等它坑过你一次你就记住了。说白了：很多人把 start:stop 读成两头都算，于是他们的 batch 少了一行（或者多了一行）。这个差一位的错（off-by-one）能藏好几个小时，因为程序根本不会报错。

1-D array = a street1-D array = 一条街

Houses numbered from 0. An index is one house number; a slice is a block of consecutive houses (1:3 = houses 1 and 2).街上的房子从 0 开始编号。一个 index 就是一个门牌号。一个 slice 就是连在一起的一排房子（1:3 = 1 号和 2 号）。

📊
2-D array = a spreadsheet2-D array = 一张表格

Point to a cell with [row, col]. A whole row is [r, :]; a whole column is [:, c]. The colon means "all of this side."用 [row, col] 指到一个格子。一整行是 [r, :]。一整列是 [:, c]。冒号的意思是「这一边全都要」。

In one line: index picks one; slice picks a range; the comma separates the axes; the colon means "everything on this axis."一句话：index 挑一个。slice 挑一段。逗号分开 axis。冒号的意思是「这条 axis 上全都要」。

⚠️
Where the analogy breaks: a slice doesn't copy the houses — it's a view, a window onto the same data, so changing the slice can change the original. We'll treat slices as plain copies for now and revisit that later.这个比喻不准的地方：slice 不会把房子复制一份 —— 它是一个 view（视图），一扇朝着同一份数据开的窗。所以你改了 slice，原来的数据也会跟着变。今天我们先把 slice 当成普通的复制品，以后再回来说这件事。

Intuition: a colon means "all of this axis", a comma means "now the next axis." The technical point: indexing/slicing is pure address arithmetic on a regular grid, so grabbing a batch or a column is O(1) bookkeeping, not a copy loop.直觉：把 : 想成「整条 axis 都要」，把逗号想成「换到下一条 axis」。往深一点说：indexing 和 slicing 在一张排得很整齐的网格上做的其实就是地址算术。所以抓一个 batch 或者一整列，是 O(1) 的记账，不是一个一个复制的循环。

🔗
Software analogy: a slice is like a database LIMIT/OFFSET over rows already sorted on disk — you name a start and a count, and the engine reads that window without touching the rest. Same idea: data[0:32] hands you a training batch by pointer, not by copying 32 rows.软件里的类比：slice 很像数据库对硬盘上已经排好序的行做 LIMIT/OFFSET。你说一个起点和一个数量，引擎就去读那一扇窗，别的行一个都不碰。data[0:32] 是同一个道理。它给你一个训练用的 batch，给的是一个指针，不是复制 32 行。

4The exact rules — and why labs slice all day准确的规则 —— 以及实验室为什么整天在 sliceMechanism & why原理和为什么

The rules, precisely准确的规则

  • Positions start at 0. x[i] is one element.位置从 0 开始。x[i] 是一个元素。
  • x[a:b] is from a up to but not including b. So its length is b − a.x[a:b] 是从 a 一直到 b，但不包括 b。所以它的长度是 b − a。
  • x[a:b:step] takes every step-th element; negative indices count from the end (x[-1] = last).x[a:b:step] 每隔 step 个取一个。负数的 index 从末尾往前数（x[-1] = 最后一个）。
  • For a grid, use one index or slice per axis, separated by commas: g[row, col]. A lone : means the whole axis.面对一张网格，每条 axis 写一个 index 或者 slice，中间用逗号隔开：g[row, col]。单独一个 : 表示整条 axis。

Why a frontier lab cares前沿实验室为什么在意这件事

You just met vLLM's PagedAttention above — here's the mechanism underneath it. Slicing is how models move data all day: grab a training batch with data[0:32], or pull one attention head's slice out of a big tensor. vLLM's exact move is to carve the KV cache into fixed-size chunks with cache[:, :seq_len] — that's what lets it reuse memory efficiently when two requests share the exact same prompt text, instead of wasting space. It happens millions of times per second.上面你刚见过 vLLM 的 PagedAttention。这里说的是它底下的机制。model 一整天搬数据靠的就是 slicing。用 data[0:32] 抓一个训练 batch。或者从一个大 tensor（张量）里把某一个 attention head 的那一片取出来。vLLM 的做法是用 cache[:, :seq_len] 把 KV cache 切成固定大小的小块。当两个请求的 prompt 文字完全一样时，这样就能把内存重复用起来，不会白白浪费。这件事每秒钟发生几百万次。

🔗
Remember this causal chain: positions are regular → any sub-region has a fixed address → you grab a batch/row/column with plain arithmetic, no copy-loop → data moves fast. An off-by-one slice (forgetting the stop is excluded) is one of the most common bugs there is.把这条因果链记住：位置排得很整齐 → 任何一小块都有固定的地址 → 抓一个 batch、一行、一列，只要做简单的算术，不用复制循环 → 数据跑得快。slice 差一位（忘了 stop 不算）是最常见的 bug 之一。
⚠️
Staff / Research Engineer Lens — two silent failures: (1) the off-by-one — x[a:b] has length b − a, so x[1:3] is 2 elements, not 3; drop a token and your labels shift by one silently. (2) the view vs. copy trap — a slice is a window onto the same memory, so writing into batch = data[0:32] can mutate your dataset in place. ⚖️ Trade-off: views are free (no copy) but aliased; when in doubt, .copy() costs memory but buys safety — say which one you chose in review.Staff / Research Engineer 视角 —— 两种不出声的错：（1）差一位 —— x[a:b] 的长度是 b − a，所以 x[1:3] 是 2 个元素，不是 3 个。少了一个 token，你的标签就悄悄错位一格。（2）view 还是 copy 这个坑 —— slice 是一扇朝着同一块内存开的窗。所以往 batch = data[0:32] 里写东西，可能会直接改掉你的数据集。⚖️ 取舍：view 不花钱（不复制），但它跟原数据共用内存。拿不准的时候用 .copy()，它多花内存，换来安全。做 code review 的时候，说清楚你选了哪一种。
🎤
Say this in an interview: "Slicing is half-open address arithmetic: x[a:b] is b − a elements and returns a view, not a copy. That's why it's cheap — no data moves — and it's exactly how a batch or a KV-cache block is carved out. The nuance is aliasing: because a slice shares memory, an in-place write can silently corrupt the source, so I copy when I need isolation."面试的时候可以这样说：「slicing 是半开区间的地址算术。x[a:b] 有 b − a 个元素，返回的是 view，不是 copy。所以它很便宜，没有数据被搬动。batch 和 KV cache 的 block 就是这样切出来的。要注意的一点是内存共用：slice 和原数据共用同一块内存，所以原地写入可能悄悄弄坏源数据。需要隔开的时候，我就复制一份。」
