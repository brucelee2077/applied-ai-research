<section class="module-section" id="s1" data-sec="what">
  <div class="sec-head"><span class="sec-num s-what">1</span><span class="sec-h"><span class="lang-en">Indexing vs. slicing — what each one does</span><span class="lang-zh">index 和 slice —— 各自做什么</span></span><span class="sec-tag"><span class="lang-en">What is it</span><span class="lang-zh">这是什么</span></span></div>
  <div class="sec-body">
      <div class="callout c-info"><span class="ic">🧭</span><div><span class="lang-en"><b>What this assumes:</b> Day 1 — you can make an array and read its <code>shape</code>. <b>No new tools today</b> — just two ways of reaching into an array.</span><span class="lang-zh"><b>这一天假设你已经会：</b>第 1 天的东西 —— 你能做出一个 array，也能读出它的 <code>shape</code>。<b>今天没有新工具</b> —— 只有两种伸手进 array 的方法。</span></div></div>

      <h4><span class="lang-en">What is indexing?</span><span class="lang-zh">什么是 indexing？</span></h4>
      <p><span class="lang-en"><span class="term" data-tip="Grabbing a single element from an array by its position number, counting from 0.">Indexing</span> means grabbing <strong>one element</strong> by its position. Positions count from <strong>0</strong>, exactly like a Python list: <code>x[0]</code> is the first element, <code>x[2]</code> the third.</span><span class="lang-zh"><span class="term" data-tip="按位置编号从 array 里拿出单个元素，编号从 0 开始数。">indexing</span> 的意思是按位置拿<strong>一个元素</strong>。位置从 <strong>0</strong> 开始数，跟 Python list 完全一样。<code>x[0]</code> 是第一个元素，<code>x[2]</code> 是第三个。</span></p>

      <h4><span class="lang-en">What is slicing?</span><span class="lang-zh">什么是 slicing？</span></h4>
      <p><span class="lang-en"><span class="term" data-tip="Grabbing a range of elements with start:stop. The stop position is excluded.">Slicing</span> means grabbing a <strong>range</strong> with <code>start:stop</code>. The catch you must remember forever: the <strong>stop is excluded</strong>. <code>x[1:3]</code> gives positions 1 and 2 — not 3.</span><span class="lang-zh"><span class="term" data-tip="用 start:stop 拿一段范围。stop 那个位置不算在里面。">slicing</span> 的意思是用 <code>start:stop</code> 拿<strong>一段范围</strong>。有一个坑你要记一辈子：<strong>stop 不算在里面</strong>。<code>x[1:3]</code> 给你位置 1 和位置 2 —— 没有 3。</span></p>

      <h4><span class="lang-en">How does it relate to what you know?</span><span class="lang-zh">它跟你已经会的东西有什么关系？</span></h4>
      <p><span class="lang-en">This is the same <code>x[0]</code> and <code>x[1:3]</code> you already use on Python lists. Arrays add one new move: for a grid you separate the dimensions with a <strong>comma</strong> — <code>g[row, col]</code>. And a lone colon <code>:</code> means "everything on this <span class="term" data-tip="One dimension of an array. A 2-D array has two axes: axis 0 = rows, axis 1 = columns.">axis</span>."</span><span class="lang-zh">这就是你在 Python list 上早就用过的 <code>x[0]</code> 和 <code>x[1:3]</code>。array 只多了一个新动作。面对一张网格，你用<strong>逗号</strong>把 dimension（维度）分开 —— <code>g[row, col]</code>。单独一个冒号 <code>:</code> 的意思是「这条 <span class="term" data-tip="array 的一个方向。一个 2-D array 有两条 axis：axis 0 是行，axis 1 是列。">axis（轴）</span> 上全都要」。</span></p>
      <p><span class="lang-en">Two symbols do all the work today: the <strong>comma</strong> (separate axes) and the <strong>colon</strong> (a range, or "all"). Keep going 👇</span><span class="lang-zh">今天的活全靠两个符号干完：<strong>逗号</strong>（分开 axis）和<strong>冒号</strong>（一段范围，或者「全都要」）。继续往下 👇</span></p>
      <div class="callout c-info"><span class="ic">🏭</span><div><span class="lang-en"><b>A real one:</b> vLLM, one of the most-used serving engines for LLMs, is built around <b>PagedAttention</b> — it slices the KV cache into fixed-size blocks the exact same way an operating system pages memory. Slicing isn't just a classroom trick.</span><span class="lang-zh"><b>真实的例子：</b>vLLM 是给 LLM 提供服务最常用的引擎之一，它的核心是 <b>PagedAttention</b>。它把 KV cache 切成一块块固定大小的 block。这个做法跟操作系统给内存分页完全一样。slicing 不是课堂上的小把戏。</span></div></div>
      <div class="callout c-warn"><span class="ic">😕</span><div><span class="lang-en"><b>Why this trips people up:</b> <code>x[1:3]</code> looks like it reaches 3, but it does not — the half-open rule feels arbitrary until it burns you. In plain terms: people read <code>start:stop</code> as inclusive, so their batch is one row short (or one too many), and the off-by-one hides for hours because nothing crashes.</span><span class="lang-zh"><b>为什么这里容易卡住：</b><code>x[1:3]</code> 看起来能取到 3，其实取不到。half-open（半开区间）这个规矩一开始会让人觉得没道理，等它坑过你一次你就记住了。说白了：很多人把 <code>start:stop</code> 读成两头都算，于是他们的 batch 少了一行（或者多了一行）。这个差一位的错（off-by-one）能藏好几个小时，因为程序根本不会报错。</span></div></div>

<section class="module-section" id="s4" data-sec="why">
  <div class="sec-head"><span class="sec-num s-study">4</span><span class="sec-h"><span class="lang-en">The exact rules — and why labs slice all day</span><span class="lang-zh">准确的规则 —— 以及实验室为什么整天在 slice</span></span><span class="sec-tag"><span class="lang-en">Mechanism &amp; why</span><span class="lang-zh">原理和为什么</span></span></div>
  <div class="sec-body">
      <h4><span class="lang-en">The rules, precisely</span><span class="lang-zh">准确的规则</span></h4>
      <ul>
        <li><span class="lang-en">Positions start at <strong>0</strong>. <code>x[i]</code> is one element.</span><span class="lang-zh">位置从 <strong>0</strong> 开始。<code>x[i]</code> 是一个元素。</span></li>
        <li><span class="lang-en"><code>x[a:b]</code> is from <code>a</code> up to <strong>but not including</strong> <code>b</code>. So its length is <code>b − a</code>.</span><span class="lang-zh"><code>x[a:b]</code> 是从 <code>a</code> 一直到 <code>b</code>，但<strong>不包括</strong> <code>b</code>。所以它的长度是 <code>b − a</code>。</span></li>
        <li><span class="lang-en"><code>x[a:b:step]</code> takes every <code>step</code>-th element; negative indices count from the end (<code>x[-1]</code> = last).</span><span class="lang-zh"><code>x[a:b:step]</code> 每隔 <code>step</code> 个取一个。负数的 index 从末尾往前数（<code>x[-1]</code> = 最后一个）。</span></li>
        <li><span class="lang-en">For a grid, use one index or slice <strong>per axis, separated by commas</strong>: <code>g[row, col]</code>. A lone <code>:</code> means the whole axis.</span><span class="lang-zh">面对一张网格，<strong>每条 axis 写一个</strong> index 或者 slice，<strong>中间用逗号隔开</strong>：<code>g[row, col]</code>。单独一个 <code>:</code> 表示整条 axis。</span></li>
      </ul>

      <h4><span class="lang-en">Why a frontier lab cares</span><span class="lang-zh">前沿实验室为什么在意这件事</span></h4>
      <p><span class="lang-en">You just met vLLM's <b>PagedAttention</b> above — here's the mechanism underneath it. Slicing is how models move data all day: grab a training <strong>batch</strong> with <code>data[0:32]</code>, or pull one attention head's slice out of a big tensor. vLLM's exact move is to carve the <span class="term" data-tip="The stored keys/values from earlier tokens that a model reuses so it does not recompute them every step. You will meet it later.">KV cache</span> into fixed-size chunks with <code>cache[:, :seq_len]</code> — that's what lets it reuse memory efficiently when two requests share the exact same prompt text, instead of wasting space. It happens millions of times per second.</span><span class="lang-zh">上面你刚见过 vLLM 的 <b>PagedAttention</b>。这里说的是它底下的机制。model 一整天搬数据靠的就是 slicing。用 <code>data[0:32]</code> 抓一个训练 <strong>batch</strong>。或者从一个大 tensor（张量）里把某一个 attention head 的那一片取出来。vLLM 的做法是用 <code>cache[:, :seq_len]</code> 把 <span class="term" data-tip="model 把前面 token 算过的 key 和 value 存下来，下一步直接拿来用，不必重算。以后会讲到。">KV cache</span> 切成固定大小的小块。当两个请求的 prompt 文字完全一样时，这样就能把内存重复用起来，不会白白浪费。这件事每秒钟发生几百万次。</span></p>
      <div class="callout c-info"><span class="ic">🔗</span><div><span class="lang-en"><b>Remember this causal chain:</b> positions are regular → any sub-region has a fixed address → you grab a batch/row/column with plain arithmetic, no copy-loop → data moves fast. An <strong>off-by-one slice</strong> (forgetting the stop is excluded) is one of the most common bugs there is.</span><span class="lang-zh"><b>把这条因果链记住：</b>位置排得很整齐 → 任何一小块都有固定的地址 → 抓一个 batch、一行、一列，只要做简单的算术，不用复制循环 → 数据跑得快。<strong>slice 差一位</strong>（忘了 stop 不算）是最常见的 bug 之一。</span></div></div>
      <div class="callout c-warn"><span class="ic">⚠️</span><div><span class="lang-en"><b>Staff / Research Engineer Lens — two silent failures:</b> (1) the off-by-one — <code>x[a:b]</code> has length <code>b − a</code>, so <code>x[1:3]</code> is 2 elements, not 3; drop a token and your labels shift by one silently. (2) the <em>view vs. copy</em> trap — a slice is a window onto the same memory, so writing into <code>batch = data[0:32]</code> can mutate your dataset in place. <b>⚖️ Trade-off:</b> views are free (no copy) but aliased; when in doubt, <code>.copy()</code> costs memory but buys safety — say which one you chose in review.</span><span class="lang-zh"><b>Staff / Research Engineer 视角 —— 两种不出声的错：</b>（1）差一位 —— <code>x[a:b]</code> 的长度是 <code>b − a</code>，所以 <code>x[1:3]</code> 是 2 个元素，不是 3 个。少了一个 token，你的标签就悄悄错位一格。（2）<em>view 还是 copy</em> 这个坑 —— slice 是一扇朝着同一块内存开的窗。所以往 <code>batch = data[0:32]</code> 里写东西，可能会直接改掉你的数据集。<b>⚖️ 取舍：</b>view 不花钱（不复制），但它跟原数据共用内存。拿不准的时候用 <code>.copy()</code>，它多花内存，换来安全。做 code review 的时候，说清楚你选了哪一种。</span></div></div>
      <div class="callout c-ok"><span class="ic">🎤</span><div><span class="lang-en"><b>Say this in an interview:</b> "Slicing is half-open address arithmetic: <code>x[a:b]</code> is <code>b − a</code> elements and returns a view, not a copy. That's why it's cheap — no data moves — and it's exactly how a batch or a KV-cache block is carved out. The nuance is aliasing: because a slice shares memory, an in-place write can silently corrupt the source, so I copy when I need isolation."</span><span class="lang-zh"><b>面试的时候可以这样说：</b>「slicing 是半开区间的地址算术。<code>x[a:b]</code> 有 <code>b − a</code> 个元素，返回的是 view，不是 copy。所以它很便宜，没有数据被搬动。batch 和 KV cache 的 block 就是这样切出来的。要注意的一点是内存共用：slice 和原数据共用同一块内存，所以原地写入可能悄悄弄坏源数据。需要隔开的时候，我就复制一份。」</span></div></div>
