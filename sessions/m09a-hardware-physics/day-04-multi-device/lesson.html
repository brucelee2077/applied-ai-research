Multi-Device Executionpmap & SPMD

Yesterday you split one big array across many devices (sharding). Today you run the same program on every device at once, each over its own shard. The tool is jax.pmap — think of it as vmap's cousin that maps across real machines instead of a batch dimension.

🎯

1What is SPMD, and what is pmap?What is it
🧭
What this assumes: basic Python/NumPy, Day 3 (jax.vmap) from this week, and Day 3's Sharding lesson (splitting an array across devices). No prior multi-device experience needed.

The problem: one program, many machines

You have several devices — a device is one piece of hardware that does the math, like a single GPU or TPU chip. You want each device to do work at the same time, not one after another. But how do you run your code on all of them together without writing a different program for each?

The idea: SPMD

SPMD stands for Single Program, Multiple Data. It means one thing: you write one function, and every device runs that same function — but each device runs it on its own slice of the data (its shard, from Day 3). Same recipe, different ingredients on each stove.

The tool: jax.pmap

pmap (short for "parallel map") takes your function and maps it across physical devices. It is vmap's cousin: vmap maps a function over a batch axis inside one device; pmap maps a function over the devices themselves, so each device gets one slice and they all run at once.

📦
p = jax.pmap(f)  →  give it an array whose first axis has one entry per device, and p(X) runs f on each device's slice in parallel.
Same mental model as vmap — leading axis is "the thing we map over" — but now that axis maps to real hardware.

Keeping devices in agreement: jax.lax.pmean

When each device computes its own number (say a gradient on its own shard), the devices need to agree on one shared value. jax.lax.pmean averages a value across all devices and gives every device the same mean back. In data-parallel training this is how all replicas average their gradients so they all take the identical update step.

📚
Official docs (optional): jax.pmap API · jax.lax.pmean API · Distributed arrays & automatic parallelization in JAX
2Four cooks, one recipe, one shared answerIntuition

Picture four cooks in a kitchen. You hand each of them the same recipe card, but each cook gets a different basket of ingredients. They all cook at the same time.

👩‍🍳👨‍🍳
pmap = same recipe, own ingredients

Every cook (device) runs the identical recipe (your function) on their own basket (their shard). Four dishes get made at once, in parallel — that is SPMD.

🥄🟰🥄
pmean = agree on the average

At the end each cook has tasted their own dish and has an opinion (a number). pmean is them pooling opinions and everyone walking away with the exact same average.

In one line: pmap is vmap that maps across real machines instead of a batch dimension; pmean is the machines agreeing on the average at the end.

⚠️
Where the analogy breaks: the cooks are not fully independent. During pmean the devices must talk to each other and exchange numbers over the hardware link — a real communication step, not just a quiet local calculation.

4The rules of pmap and pmean, and why they matterHow & why

The rules

  • jax.pmap(f) returns a new function. It maps f over axis 0 of each input — but that axis must have one entry per device. So you feed it arrays shaped (n_devices, ...).
  • Inside f, you write code for one device's slice — no device dimension to think about. pmap handles running it everywhere and puts the results back with a leading device axis.
  • To average across devices, give pmap an axis_name, then call jax.lax.pmean(value, axis_name) inside f. Every device gets the same averaged result back.
  • On a single CPU you can still practice: set the env var XLA_FLAGS=--xla_force_host_platform_device_count=8 to make JAX simulate 8 devices before importing jax.
✅
jax.pmap(lambda g: jax.lax.pmean(g, 'devices'), axis_name='devices')(grads)
"Run on every device; average each device's gradient across the group named 'devices'." Every replica walks away with the identical averaged gradient.

Why it matters

  • Data parallelism — the main way to train big models: copy the model to every device, give each device a different slice of the batch, then pmean the gradients so all copies stay identical.
  • Same function, no rewrite — you write single-device logic; pmap spreads it across hardware, just like vmap spread it across a batch axis.
  • Correctness — pmean guarantees every replica takes the exact same update, so the copies never drift apart.
🔗
Causal chain: sharding (Day 3) splits data across devices → pmap runs one program on every device (SPMD) → pmean averages gradients so all replicas agree → data-parallel training that scales across hardware.

The staff lens — one silent failure, one trade-off

The whole correctness of data-parallel training rests on one line — the gradient average — and forgetting it fails quietly, not loudly.

⚠️
Failure mode (silent): forgetting pmean, so replicas drift apart. pmap happily runs your step on every device even if you never average the gradients. Each replica then updates its weights using only its own slice of the batch, so the copies slowly diverge. Shapes are fine, no exception is raised, and the loss still falls — but you are no longer doing one coherent large-batch update, you are running N different half-trained models that print one averaged-looking number. In code review, a senior engineer checks that gradients pass through jax.lax.pmean(grads, axis_name) before the optimizer step, and that the axis_name in pmap and in pmean match.
⚖️
Trade-off: more throughput vs. a fixed sync cost every step. Data parallelism lets you process a bigger batch per step by copying the model to every device — near-linear speedup on the compute. What you pay is a gradient AllReduce on every single step: as you add devices, that fixed communication cost grows and eventually caps the speedup. In a design review, this is why very large runs mix data parallelism with other strategies (sharding the model itself) instead of just adding more data-parallel replicas forever.
