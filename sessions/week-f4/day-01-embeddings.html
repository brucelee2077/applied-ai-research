Module 4 · Represent · Day 1

Words to Numbers
Embeddings: Meaning as Geometry

Transformers — the models behind every chatbot — start with a simple problem: a computer can't do math on the word "cat." So the first step of every language model turns each word into a list of numbers, called an embedding, arranged so that similar words sit close together.

🎯 By the end, you'll be able to: explain what an embedding is, look one up as a row of a matrix, and measure how "similar" two word-vectors are with a dot product.
1 · WHAT IS ITTurning words into vectors✓
🧭
What this assumes: M1 (arrays, indexing a row, the dot product). No transformer background needed — this is the very first step of one.

The problem

A neural network only does math on numbers (M1–M3). But language is made of tokens (words or word-pieces). So step one of every language model is: turn each token into numbers.

What is an embedding?

An embedding is a vector (a list of numbers) that stands for a token's meaning. The trick: the numbers are arranged so that similar words get similar vectors. "cat" and "dog" land close; "cat" and "car" land far apart.

How is it stored?

As a big lookup table — an embedding matrix. Give it token id i and it hands back row i (indexing a row — M1 Day 2!). Those numbers aren't hand-set; they're learned during training (M3's loop), so meaning gradually becomes geometry. Keep going 👇

2 · INTUITIONA map of meaning✓
🗺️
Words as places on a map

Each word is a point. Related words cluster: animals here, vehicles there. The position carries the meaning, and closeness means similarity.

🎨
Like a color code

A color is just three numbers (R, G, B). A word is a longer list of numbers. Nearby lists = alike; and directions can carry meaning ("king − man + woman ≈ queen").

In one line: an embedding turns each word into a point in space so that meaning becomes distance and direction.

⚠️
Where the analogy breaks: a real embedding isn't 2-D — it's hundreds of dimensions (a size called d_model). We draw 2-D pictures, but the model works in a much bigger space you can't fully visualize.

4 · MECHANISM & WHYThe lookup table — and why every LLM starts here✓

The mechanism

  • The embedding matrix has shape (vocab_size, d_model): one row per token, each row a vector of length d_model.
  • Embedding a token = indexing its row: E[id] (M1 Day 2).
  • Similarity between two vectors = a dot product (M1 Day 4): bigger means more alike.
  • The numbers are learned by the training loop (M3), so words used in similar contexts drift close together.

Why a frontier lab cares

This is step 1 of every language model: text → tokens → embeddings, and everything after (attention, the layers you built in M2) operates on these vectors. d_model is a core size knob, and the embedding matrix is a big share of a model's parameters (vocab is often 50k–250k rows). Get the input representation right and the rest has something meaningful to work with.
