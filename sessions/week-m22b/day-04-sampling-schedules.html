Module 22b · Generate · Day 4

Sampling:
Developing the Photo Fast or Slow

You have a trained denoiser. Now you must actually run the reverse walk to make a picture — and there is a choice hidden here. The classic way, DDPM, takes many small steps and adds a little fresh noise each time. A faster way, DDIM, skips steps and is fully repeatable, no random kick. Fewer steps is faster but can look rougher; more steps is slower but sharper. Today you learn to trade speed for quality by picking how many steps to take.

🎯 By the end, you'll be able to: tell DDPM (many steps, random) apart from DDIM (fewer steps, deterministic), explain how the step count trades speed for quality, and say why the schedule choice matters.
1 · WHAT IS ITTwo ways to run the reverse walk✓
🧭
What this assumes: Day 2 — the reverse process removes a little noise per step, run from pure noise down to a picture. Day 3 — the network was trained to guess the noise. Today you choose how to run that reverse walk when you actually generate.

The choice: how to sample

Generating a picture means running the reverse walk. But you get to pick the rules of that walk. This choice is called the sampler. The trained network stays the same — you just decide how to use it.

DDPM: many small, noisy steps

DDPM is the original way. It walks one timestep at a time, all T of them, and adds a small fresh random noise at each step. Because of that random kick, running it twice from the same start gives two different pictures. It is high quality but slow — 1000 network calls per image.

DDIM: fewer, repeatable steps

DDIM is the faster way. It can skip timesteps — take 50 big steps instead of 1000 tiny ones — and it adds no fresh noise. Because there is no random kick, it is deterministic: the same starting noise always makes the same picture. Far fewer network calls, so it is much faster.

The trade you are making

Fewer steps means the image is finished faster but each step is a bigger, rougher guess, so quality can drop. More steps means slower but smoother, sharper results. Picking the step count is the speed-versus-quality dial for generation. Keep going 👇

2 · INTUITIONDeveloping a photo fast or slow✓
🎞️
The darkroom

Old photos were developed in a darkroom: a blank sheet slowly reveals an image as it sits in chemicals. Leave it the full time and you get a crisp, rich photo. Pull it out early and you save time, but the image is grainier and less detailed. The reverse walk is that developing — and the number of steps is how long you leave the sheet in.

🎲
Same or different each time?

DDPM shakes the tray a little at each moment (the random kick), so two developed sheets from the same start look slightly different. DDIM keeps a steady hand — no shaking — so the same start always develops into the exact same photo. Steady hand = repeatable.

In one line: sampling is developing a photo — many slow steps (DDPM) give a rich result, fewer fast steps (DDIM) save time but can look rougher, and DDIM's steady hand makes the result repeatable.

Why would you ever want fewer steps? Speed. A single picture with 1000 steps means 1000 network calls — slow and costly. DDIM with 50 steps is 20 times faster and usually looks nearly as good. When you need many pictures quickly, you turn the step dial down and accept a little roughness.

⚠️
Where the analogy breaks: a real photo only reveals what the film already captured. Here nothing was captured — the network invents the picture from random noise. And unlike film, you can change the developing rule (DDPM vs DDIM) without changing anything about the trained network.

4 · MECHANISM & WHYCounting the speed-vs-quality trade by hand✓

Step 1 — in plain words

Both samplers call the trained network once per step. So the cost of making one picture is simply the number of steps times the cost of one network call. DDPM uses all T steps and adds a random kick each time. DDIM uses a smaller chosen number of steps and adds no kick. Fewer steps means fewer network calls, which means less time — but each remaining step must cover more ground, so it is a rougher guess.

Step 2 — the formula

🧮
network_calls_per_image = number_of_steps
DDPM: steps = T (e.g. 1000), + random kick each step
DDIM: steps = S (e.g. 50), no kick → deterministic
speedup ≈ T / S

Symbols: T = the full number of training timesteps (often 1000). S = the smaller number of steps you choose for DDIM. network_calls_per_image = how many times the network runs to make one picture, which sets the time. speedup ≈ T / S = roughly how much faster DDIM is than full DDPM.

Step 3 — a worked example

Say one network call takes 20 ms. Compare full DDPM at T = 1000 steps to DDIM at S = 50 steps:

🔢
DDPM time = 1000 × 20 ms = 20,000 ms = 20 s
DDIM time = 50 × 20 ms = 1,000 ms = 1 s

speedup = 1000 / 50 = 20× # DDIM is 20 times faster

DDIM finishes in one second instead of twenty — a 20× speedup — for a small drop in sharpness. If you push S too low (say 10 steps), each step covers so much ground that the picture can look rough or lose fine detail. The right S balances your time budget against how crisp the result must be.

Why the schedule choice also matters

  • Where the steps land: with few steps, you space them along the noise schedule so more effort goes where the picture forms fastest — a smart schedule beats evenly-spaced steps.
  • DDIM is repeatable: no random kick means the same seed gives the same image, which is great for debugging and for controllable generation.
  • DDPM's kick adds variety: the random noise per step makes DDPM explore more, sometimes helping diversity at the cost of speed.
🔗
The big picture: the trained network never changes — sampling is a runtime dial. Modern systems use fast samplers (DDIM-style, and newer ones) to make pictures in a handful of steps. Tomorrow you put it all inside a small latent space and add text control — the recipe behind Stable Diffusion.
