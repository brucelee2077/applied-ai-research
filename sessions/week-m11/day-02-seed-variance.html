Module 11 · Scale · Day 2

Seed
Variance

You run the exact same training twice. Same code, same data, same settings. And you get two different scores. Nothing is broken — this is normal. Training uses random choices, and one number controls them: the seed. Today you learn why one run is not enough, why you should run a few seeds and report a mean with a spread, and how to answer the question that haunts every researcher: "is my +0.3% real, or just seed luck?"

🎯 By the end, you'll be able to: explain why the same setup gives different scores, run a few seeds and report a mean ± spread, and decide whether a small gain is real or just noise from the random seed.
1 · WHAT IS ITThe same setup gives different scores✓
🧭
What this assumes: you can run a training and read a score (from M1 and M2), and you know the one-variable ablation rule from Day 1. Today we handle a new problem: even with nothing changed, two runs give two different numbers.

The surprise

You train a model. Score: 82.1%. You run the exact same thing again — same code, same data, same settings. Score: 81.7%. You did not touch anything. So why did the number move? Because training makes many random choices along the way, and each run makes them differently.

Where the randomness comes from

Training is full of dice rolls: the starting weights are random, the data is shuffled into a random order, and some layers drop random parts on purpose. All of this randomness is steered by one starting number called the seed. Change the seed and every dice roll comes out differently — so the final score wobbles too.

The wobble has a name

How much your score jumps around from seed to seed is called seed variance. It is not a bug. Every real model has some. Your job is not to remove it — it is to measure it, so you know how big a gain has to be before it means anything.

The rule: never trust one run

One run gives one number, and that number carries hidden luck. So you run the same setup a few times with different seeds and report a mean ± spread: the average score, plus how much it moves. This is the honest way to report a result. Keep going 👇

2 · INTUITIONJudging a loaded dice needs many rolls✓
🎲
One roll tells you nothing

A friend says a dice is loaded to favor six. You roll it once and get a six. Is it loaded? You cannot say — a fair dice rolls a six too, one time in six. One roll is just luck, in either direction.

📊
Many rolls tell the truth

So you roll it thirty times. If sixes come up far more often than one in six, now you can say it is loaded. The pattern across many rolls beats the luck of any single roll.

In one line: one training run is one dice roll — mostly luck. Running a few seeds is rolling many times, so you can see the true tendency through the noise.

The seed is which way the dice happened to land this time. A "+0.3% better" from a single run is like one lucky six: it could easily be seed luck. Run a few seeds for each setup and compare their averages, and you can finally tell a real gain from a fluke.

⚠️
Where the analogy breaks: a dice has a known, simple chance for each face. A model's seed variance has no neat formula — you cannot predict it, you can only measure it by actually running several seeds. And a few runs of a slow model is far more costly than tossing a dice.

4 · MECHANISM & WHYMean and spread, worked out by hand✓

Step 1 — in plain words

Run the same setup with a few different seeds. You get a few scores. The mean is their average — your best single guess. The standard deviation (std) says how far, on average, the scores sit from that mean — how big the wobble is.

Step 2 — the formulas

🧮
mean = ( x1 + x2 + ... + xn ) / n
std = sqrt( average of (each xi − mean)² )
# report it as: mean ± std

Symbols: x1 ... xn = the score from each seed. n = how many seeds you ran. mean = the average. (xi − mean)² = how far one score is from the mean, squared so it is always positive. sqrt = square root, which brings the units back to normal. The result is the spread.

Step 3 — a worked example

You run 4 seeds. The scores are 82.1, 81.7, 82.6, 81.6.

🔢
scores = [82.1, 81.7, 82.6, 81.6]
mean = (82.1+81.7+82.6+81.6)/4 = 328.0/4 = 82.0

gaps² : 0.1² + 0.3² + 0.6² + 0.4²
     = 0.01 + 0.09 + 0.36 + 0.16 = 0.62
std = sqrt(0.62/4) = sqrt(0.155) ≈ 0.39

report: 82.0 ± 0.4

So this setup scores about 82.0%, and any single run may land roughly 0.4% above or below. That ± 0.4 is your noise size. Now the punchline: if a new idea reports 82.3% from one run, its +0.3 is smaller than the 0.4 wobble — it is very likely seed luck, not a real gain.

Why this is a big deal

  • One number hides its luck: "82.3%" looks solid but could shift by 0.4% on a rerun. The mean ± spread shows that honestly.
  • The spread sets the bar: a gain must clearly beat the wobble before you can call it real. Small gains need more seeds to prove.
  • More seeds, steadier mean: the average of many runs jumps around less than any single run, so more seeds give a more trustworthy number.
🔗
The big picture: "mean ± spread" is how every serious result is reported. It sets up tomorrow perfectly — Day 3 turns that spread into an error bar, a visual noise band, so you can see at a glance whether two results are really different.
