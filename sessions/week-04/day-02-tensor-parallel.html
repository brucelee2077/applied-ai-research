Tensor Parallelism
Splitting a Single Matmul

Yesterday you copied the whole model onto each device. But what if a single weight matrix is too big to fit, or one matmul is too slow? Today you learn to split the matmul itself across devices — column by column, or row by row.

🎯 By the end, you'll be able to: explain what it means to split a matmul, describe column-parallel (concatenate outputs) vs. row-parallel (all-reduce partial sums), and say why a transformer block pairs them so only one all-reduce is needed.
1 · WHAT IS ITWhat is tensor parallelism?✓
🧭
What this assumes: you can multiply two matrices (a matmul: Y = X @ W), and you saw data parallelism yesterday (each device holds a full copy of the model and processes a slice of the data). No prior tensor-parallel experience needed.

The problem: one matmul, too big for one device

A big model layer is often just one large matrix multiply: inputs X times a weight matrix W. Two things can go wrong on a single device:

  • The weight matrix W is too big to fit in one device's memory.
  • The matmul is too slow for one device to do alone in the time you have.

Yesterday's data parallelism (DP) does not help here. DP copies the whole weight matrix onto every device — so if W does not fit on one device, it does not fit under DP either. You need a different cut.

The answer: split the matmul itself

Tensor parallelism (TP) means you take a single matmul and split it across devices. Instead of copying the whole weight, you give each device a piece of the weight matrix and have them work together. There are two ways to cut:

  • Column-parallel: split the weight's columns across devices. Each device computes a different part of the output. You then lay the pieces side by side (concatenate) to rebuild the full output.
  • Row-parallel: split the weight's rows across devices. Now each device computes a partial sum of the same output. You add all the partial sums together with an all-reduce (a group operation where every device shares its numbers and everyone ends up with the total).

Why both, and why they come in a pair

Transformers stack a column-parallel layer directly followed by a row-parallel layer (this pattern shows up in both the attention block and the MLP block). The clever part: when you arrange them this way, the two layers together need only one all-reduce per block. That single communication is the price you pay for splitting the work.

📦
DP vs TP in one line: DP replicates the whole model and splits the data. TP splits the model's weights (one matmul at a time) and every device sees the same data.

2 · INTUITIONA giant multiplication done by a team✓

Imagine one huge multiplication that is too much for one person. So a team splits the work. There are two natural ways to divide it — and they finish in two different ways.

📊➡️📊
Column-parallel = lay pieces side by side

Each teammate computes some of the output columns. When everyone is done, you just place their answers next to each other. No adding needed — the finished output is already complete.

➕➕➕
Row-parallel = add up partial sums

Each teammate computes a partial sum for the same output. No single answer is finished until everyone shares their numbers and you add them all up. That group add-up is the all-reduce.

In one line: column-parallel finishes by concatenating pieces (cheap); row-parallel finishes by all-reducing partial sums (a real communication step).

⚠️
Where the analogy breaks: real devices do not "hand papers to each other" one at a time. The all-reduce is a single coordinated step over a fast network link, and it must complete before the next layer can run — so it stalls compute if the link is slow.

4 · HOW & WHYThe two cuts, the one all-reduce, and why the pair matters✓

The rules

  • Column-parallel. Split W by columns: W = [W_a | W_b]. Device 0 computes X @ W_a, device 1 computes X @ W_b. Each holds a slice of the output. Rebuild the full output by concatenating the slices — no adding, so no all-reduce here.
  • Row-parallel. Split W by rows and split X by columns to match. Each device computes a partial sum over its slice. The true output is the sum of the partial sums, so you finish with an all-reduce to add them across devices.
  • The pair. Put a column-parallel layer first, then a row-parallel layer. The column layer's concatenated output feeds straight into the row layer with no communication in between. Only the row layer's final sum needs the all-reduce.
  • One all-reduce per block. Because of that pairing, a whole transformer block (attention or MLP) needs just one all-reduce, not two.
✅
col: Y = concat(X@W_a, X@W_b)  then  row: Z = all_reduce(Y_a@V_a + Y_b@V_b)
The first layer's split output is already the right input to the second layer's split — so the all-reduce only happens once, at the very end of the block.

Why it matters

  • Fits and speeds up one matmul — TP is the tool when a single weight or matmul is the bottleneck, which DP cannot solve.
  • Communicates inside every layer — unlike DP (which syncs gradients once per step), TP does an all-reduce within each block, every forward and backward pass.
  • Needs a fast interconnect — because that all-reduce is on the critical path of every layer, TP only pays off when devices are linked by a very fast network (e.g. NVLink, TPU mesh links). Across slow links it stalls.
🔗
Causal chain: one matmul too big for a device → split W across devices (column or row) → column concatenates, row all-reduces → pair them so a block needs one all-reduce → cheap only on a fast interconnect.

7 · PRODUCESimulate column- and row-parallel matmul across 2 "devices"✓

Today's task: simulate both TP cuts on a single machine (2 "devices" are just two array slices) and prove each one equals the single-device matmul. No real accelerators needed.

Acceptance criteria

  • Build inputs X and a weight W with jnp, and compute the single-device answer full = X @ W.
  • Column-parallel: split W by columns into two halves, compute X @ W_a and X @ W_b, concatenate along axis 1, and assert it equals full.
  • Row-parallel: split W by rows and X by columns, compute the two partial sums, add them (the simulated all-reduce), and assert the sum equals full.
  • Print shapes at every step so the split is visible.
