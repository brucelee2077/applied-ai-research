Module 1 · Represent · Day 3

Broadcasting & dtypes
Math Between Different Shapes

You've built arrays, sliced them, and read their shape. But what happens when you add two arrays of different shapes? And why does it matter whether a number is stored as float32 or float64? Both answers decide how much memory a model eats.

🎯 By the end, you'll be able to: predict whether two shapes can be added, state the one broadcasting rule, and explain why float32 uses half the memory of float64.
1 · WHAT IS ITTwo ideas: broadcasting and dtype✓
🧭
What this assumes: Days 1–2 — arrays, shape, and that x + 10 adds to every element. No new tools — two ideas that ride on what you have.

What is broadcasting?

Broadcasting is NumPy's rule for doing math between arrays of different shapes. It automatically "stretches" the smaller one to fit the larger, so you never write a loop. You already used the simplest case on Day 1: x + 10 stretched the single number 10 across every element.

What is a dtype?

A dtype (data type) is the one kind and size every element in an array shares — like int64, float32, or float64. It decides two things: what values fit (whole numbers vs decimals) and how many bytes each number costs.

Why put them together today?

Both are about doing math efficiently at scale. Broadcasting lets one small array (like a bias) act on a huge one with no copies. The dtype decides the memory bill — and that bill is what forces the whole quantization story you'll meet later. Keep going 👇

2 · INTUITIONA stamp, and a set of boxes✓
🖊️
Broadcasting = one stamp

To add 10 to every cell, you don't rewrite "10" in each one. You press one stamp across the whole grid. NumPy stretches the small thing to cover the big thing.

📦
dtype = the size of the box

Each number sits in a box. float64 is a big box (8 bytes, lots of precision); float32 a smaller box (4 bytes); bfloat16 tiny (2 bytes). Smaller box = less memory.

In one line: broadcasting stretches a small shape to match a big one; dtype is how large each number's box is.

⚠️
Where the analogy breaks: broadcasting doesn't actually make copies — the "stretch" is virtual, so it costs no extra memory. And a smaller dtype box isn't free: squeeze too hard and you lose precision. That trade-off is the heart of quantization later.

4 · MECHANISM & WHYThe one rule, the byte table, and why money is bytes✓

The one broadcasting rule

Line the two shapes up from the right. Going right-to-left, each pair of dimensions must be either equal, or one of them is 1 (or missing). The size-1 (or missing) side is the one that stretches. If a pair is neither equal nor 1, it's an error.

✅
(2, 3) + (3,) → align right: 3 vs 3 ✓, then 2 vs missing ✓ → result (2, 3).
❌
(2, 3) + (2,) → align right: 3 vs 2 — not equal, neither is 1 → error.

The byte table

  • float64 = 8 bytes · float32 = 4 bytes · bfloat16 = 2 bytes each.
  • Memory of a tensor = number of elements × bytes/element. Halve the bytes → halve the memory.

Why a frontier lab cares

Bytes are money and speed. A 7-billion-parameter model in float32 needs ~28 GB just for weights; in bfloat16, ~14 GB — the difference between fitting on one chip or not. Broadcasting is how a bias vector (features,) gets added to a whole batch (batch, features) with no copy.

🔗
Remember this chain: broadcasting → one op covers many shapes, no copies → less code + less memory. dtype → fewer bytes per number → bigger models fit on the same hardware. Every quantization trick later is just this dial.
