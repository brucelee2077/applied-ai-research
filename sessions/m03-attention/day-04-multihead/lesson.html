Module 4 · Represent · Day 4

Multi-Head AttentionMany Views at Once

One attention (Day 3) learns one kind of relationship. But a sentence has many at once — who did what, which adjective goes with which noun, what a pronoun refers to. Multi-head attention runs several attentions in parallel, each free to focus on something different, then merges their findings.

🎯
By the end, you'll be able to: explain why transformers use multiple heads, and describe the split → attend → concatenate → project pipeline.
1Several attentions, side by sideWhat is it
🧭
What this assumes: M4 Day 3 (one attention = softmax(Q@Kᵀ/√d_k)@V) and M1 Day 4 (matmul). Nothing new needed.

The limitation of one head

A single attention — one head — produces one attention pattern. It can learn to track, say, the subject of a verb. But it can only do one such job at a time.

The fix: multiple heads

Multi-head attention runs h attentions in parallel. Each head has its own W_Q, W_K, W_V, so each can focus on a different pattern. To keep the cost the same, the model dimension d_model is split across heads: each head works in size d_k = d_model / h.

Putting them back together

Run all heads, concatenate their outputs back to length d_model, then mix them with one final learned matrix W_O. The result is one richer vector per word. Keep going 👇

🏭
A real one: Llama 3 and Mistral both ship Google's GQA trick in production — sharing Keys/Values across groups of heads to shrink memory, instead of giving every head its own full copy.
😕
为什么这里容易卡住 · Why this trips people up: 听起来 h 个头应该是 h 倍计算量，其实差不多。In plain terms: people expect "more heads = more compute", but total cost is roughly flat — splitting d_model across heads makes each head work in the smaller size d_k = d_model / h. You are re-slicing the same budget, not adding to it.

Each head = a specialist

One head watches grammar, another tracks long-range references, another links adjectives to nouns. Each reads the sentence with a different lens, at the same time.

Many highlighters, one summary

Like reading with several colored highlighters, each marking a different pattern — then combining all the highlights into one understanding of the word.

In one line: split into several small attentions that each specialize, then merge their results into one vector.

直觉 / Intuition: 一个头只能盯一种关系，多个头就像几支不同颜色的荧光笔同时读句子。 The technical point is that each head runs its own attention on a smaller d_k-sized slice, so the model tracks several relationships at once and then merges them.

⚠️
Where the analogy breaks: nobody assigns each head a job — they specialize on their own through training (M3). And the heads run in parallel and cost about the same as one big attention, because each works in the smaller size d_k.

4Split, attend, concat, project — and why every model does itMechanism & why

The pipeline

  1. Split: give each of h heads its own W_Q, W_K, W_V, projecting into size d_k = d_model / h.
  2. Attend: each head runs scaled dot-product attention (Day 3) on its own Q, K, V.
  3. Concat: stack the h head outputs back to length d_model.
  4. Project: multiply by W_O to mix the heads into the final output.
🪜
Math Ladder — split, attend, merge
1 · In words: split the model width into h smaller heads, let each run its own attention on a slice, stitch the results back together, and mix them with one matrix.
2 · The formula: d_k = d_model / h; MultiHead(x) = Concat(head₁,…,head_h)·W_O, where headᵢ = Attention(x·W_Qⁱ, x·W_Kⁱ, x·W_Vⁱ) — d_model = full width; h = number of heads; d_k = per-head width; W_O has shape (d_model, d_model).
3 · Tiny numbers: d_model=4, h=2 → d_k=2. Two heads each output a length-2 vector; concat → length 4; ·W_O (4×4) → length 4. Same width in, same width out.
4 · Sanity check: h must divide d_model, and the concat width h·d_k must equal d_model before W_O. Push h too high (d_model=512, h=64 → d_k=8) and each head is too small to hold a useful subspace.

Why a frontier lab cares

Every real transformer is multi-head — small models use 8–16 heads, big ones 32–128 (Llama 3's biggest runs 128). Heads visibly specialize (some track syntax, some copy earlier tokens). It also sets up a big inference cost: the Keys and Values for every head must be cached, which is exactly the cost GQA / MQA — the trick Llama 3 and Mistral ship in production, per the teaser above — was built to cut, by sharing K/V across groups of heads instead of giving each head its own full copy. Multi-head is the last piece of the attention block.

🔗
Remember this chain: split d_model into h heads → each attends with its own Q/K/V → concat the outputs → W_O mixes them. Stack this attention block with the feed-forward layers from M2 and you have a transformer.

The staff lens — one silent failure, one trade-off

Knowing the pipeline is not enough. A staff engineer also knows the way it breaks without an error, and the knob you are really turning when you set the head count.

⚠️
Failure mode (silent): the wrong reshape/transpose when splitting heads. Splitting (seq, d_model) into (h, seq, d_k) takes a reshape and a transpose in the right order. Get the order wrong and the shapes can still line up — so nothing crashes — but each head now attends over scrambled slices of the vector. The model trains and the loss drops; the heads just quietly stop specializing. A senior engineer catches this in code review by printing the per-head shapes, not by waiting for a crash.
⚖️
Trade-off: more heads vs. wider heads. Total compute is about the same however you slice it, because d_k = d_model / h. More heads means more independent relationship channels, but each is lower-resolution; fewer heads means richer per-head subspaces but fewer patterns tracked at once. Push h too high and d_k shrinks so small a head can't hold a useful subspace. That balance is a design-review call — and it's the same axis GQA / MQA trade along to shrink the KV cache.
🎤
Say this in an interview: "Multi-head attention runs h attentions in parallel, each with its own Q/K/V projections into a d_k = d_model/h subspace, then concatenates the heads and mixes them with an output matrix W_O. Different heads specialize on different relationships at roughly the same total cost as one big attention. The nuance is the head-count trade-off: too many heads shrinks d_k until each head is too low-dimensional to be useful — and it's the same axis GQA/MQA trade along to shrink the KV cache at inference."
