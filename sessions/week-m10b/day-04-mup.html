Module 10b · Scale · Day 4

muP & Hyperparameter Transfer

Training one giant model can cost millions of dollars. So you cannot try 50 learning rates on it to find the best. muP (maximal update parameterization) solves this: tune the settings on a small, cheap model, then reuse the exact same settings on the huge one — with no re-tuning. The best learning rate stays the same as the model grows. Today you learn why naive scaling breaks and how muP fixes it.

🎯
By the end, you'll be able to: explain why the best hyperparameters normally shift when a model gets bigger, say what muP and depth-scaled init do, and describe how tuning on a small model transfers zero-shot to the big one.
1Tune small, then reuse the settings on bigWhat is it
🧭
What this assumes: from Day 3 you know the learning rate and its schedule are settings you must choose. Today's problem: how do you choose them for a model so big you can only afford to train it once?

The dials you must set

Before training you must pick several hyperparameters: the learning rate, how big the starting weights are, and more. Pick badly and the run is slow or spikes. Finding good values normally means training many times and comparing — a search.

The problem: you cannot search on a giant model

A search needs dozens of runs. On a small model that is cheap. On a model that costs millions per run, it is impossible. Worse, the best learning rate for a small model is usually not the best for a big one — so you cannot just copy the small model's setting over.

Why the best setting shifts — naive scaling breaks

When you make a model wider the usual way, the sizes of the numbers inside it change with the width. A learning rate that was perfect at width 256 is now too big or too small at width 4096. The dial has moved. This is naive scaling breaking.

The fix: muP

muP (maximal update parameterization) changes how the initial weights and per-layer learning rates are scaled so the internal signals stay the same size as the model widens. Then the best learning rate no longer moves. Tune it on a tiny model, copy it straight to the giant one. Add depth-scaled init for depth. Keep going 👇

2A wind-tunnel scale model of an airplaneIntuition
✈️
The scale model

Before building a real airplane, engineers test a small model in a wind tunnel. It costs almost nothing compared to the real plane. If the model is built to the right rules, what they learn from it — how the wings behave — carries over to the full-size plane. They do not have to crash real planes to learn.

📐
The scaling rules matter

The model only predicts the real plane if it is built with the correct scaling rules (how forces change with size). A model built with the wrong rules tells you nothing. muP is the set of correct rules for neural networks: build the small model right, and its best settings match the big one.

In one line: muP is a wind tunnel for training — tune a cheap small model that is built with the right scaling rules, and its best hyperparameters transfer straight to the huge model.

Without muP, it is like using a paper airplane to predict a jumbo jet — the wrong scaling rules, so nothing transfers. The best learning rate you found on the small model would be wrong on the big one. muP is what makes the small test trustworthy.

⚠️
Where the analogy breaks: a wind-tunnel model is a shrunken copy of the same shape. A muP small model is not a shrunken big model — it is narrower (fewer neurons per layer). What transfers is the tuning knobs, not the trained weights. You still train the big model from scratch; you just skip the expensive search.

4Why width changes signal size — and how muP cancels itMechanism & why

Step 1 — in plain words

Inside a layer, each output neuron adds up many inputs times their weights. The more inputs (the wider the layer), the more terms in that sum, so the sum tends to get bigger just because there are more things added. If the sum grows with width, the best learning rate has to shrink with width to keep steps the right size. muP scales the weights so the sum stays the same size no matter the width.

Step 2 — the formula

🧮
pre-activation y = Σᵢ wᵢ xᵢ (i = 1 … n) # sum over n inputs
naive: size of y grows with n
muP: scale weights by 1/n → size of y stays steady as n grows

Symbols: y = one neuron's value before the activation. wᵢ = a weight. xᵢ = an input. n = the width, the number of inputs. Σᵢ = add over all n inputs. Naively, more terms means a bigger y. muP scales the contribution by 1/n so y stays the same typical size at any width.

Step 3 — a worked example

Say each term wᵢ xᵢ is about 1 on average. Compare a narrow and a wide layer:

🔢
narrow n=4: naive y ≈ 4×1 = 4   | muP y ≈ (1/4)×4 = 1
wide n=64: naive y ≈ 64×1 = 64 | muP y ≈ (1/64)×64 = 1

naive: signal jumped 4 → 64 as width grew (LR must change)
muP: signal stayed 1 → 1 (same LR works at any width)

Under naive scaling the neuron's value jumped from 4 to 64 just from widening. That is why the old learning rate no longer fits. Under muP the value stayed near 1 at both widths — so the same learning rate is still correct. The dial stopped moving.

What muP gives you, and the depth partner

  • Zero-shot transfer: tune the learning rate (and other dials) on a small width, copy them to the big width, no re-tuning.
  • Cheap search: the whole search runs on a model that costs a tiny fraction of the real one.
  • Depth-scaled init: muP handles width; scaling the initial weights by the number of layers keeps signals steady as the model gets deeper too.
⚠️
muP is not free magic. You must apply the right scaling to every layer type, and a bug in the setup silently breaks transfer — the small-model tuning would then mislead you. Teams verify transfer by checking that the best learning rate really is the same across two or three widths before trusting it.
🔗
The big picture: Days 1–3 kept a single run stable. muP lets you choose that run's settings without betting the budget. Day 5 puts everything together into one pre-flight checklist for a real training run.
