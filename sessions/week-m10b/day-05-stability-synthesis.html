Module 6 · Represent · Day 1

Convolution
& Pooling

A photo is a huge grid of numbers. A normal neural network would need millions of weights just to look at it once. A convolution is smarter: it uses one tiny grid of numbers — a filter — and slides it across the whole image, reusing the same weights everywhere. Then pooling shrinks the result while keeping what matters. This is how a machine starts to "see".

🎯 By the end, you'll be able to: explain a convolution as a small filter sliding over an image with shared weights, compute one output value by hand on a tiny grid, and say what pooling does and why we downsample.
1 · WHAT IS ITA tiny filter that slides across the image✓
🧭
What this assumes: you know that an image is a grid of numbers (pixels), and you know matrix multiply and the training loop from M4–M5. Today we swap the "every pixel talks to every neuron" idea for something much cheaper and smarter.

The problem with a plain network

A small photo of 224 by 224 pixels is over 50,000 numbers. If you connect every pixel to every neuron, the first layer alone needs tens of millions of weights. That is slow, hungry for memory, and it throws away a key fact: pixels that sit next to each other belong together.

The fix: a convolution

A filter is a tiny grid of numbers — often just 3 by 3. A convolution slides this filter over the whole image. At each stop, it multiplies the numbers that line up and adds them into one output number. Slide, multiply-add, write one number. Repeat.

The magic word: shared weights

The same filter is used at every position. This is called weight sharing. Learn one edge-detector once, and it finds edges anywhere in the picture. Nine weights can scan a whole image, instead of millions.

Then: pooling shrinks it

After a convolution you get a grid of "how strongly did the pattern match here" numbers, called a feature map. Pooling shrinks that map by keeping only the strongest value in each small block. Smaller map, same important signal. Keep going 👇

2 · INTUITIONA flashlight scanning for a pattern✓
🔦
The flashlight

Imagine a dark room with a picture on the wall. You hold a small flashlight and move it across the picture, one spot at a time. At each spot the light shows a small patch. The filter is your flashlight: it only sees one small patch at a time.

🔎
Looking for one thing

Now say you are only looking for one shape — a corner. At each patch you ask "is there a corner here?" and write down how sure you are. Do this at every spot and you get a map of where corners are. That map is the feature map.

In one line: a convolution is a small pattern-detector (the flashlight) dragged over the whole image, writing down "how much did I find my pattern here" at each spot.

Pooling then walks over that map of matches and, in each little block, keeps only the strongest one. It is like reading a page and keeping only the loudest word from each paragraph — the map gets smaller but the signal survives.

⚠️
Where the analogy breaks: a real flashlight only reveals what is already there. A filter also carries its own numbers (weights), so it does not just show the patch — it reacts more strongly to some shapes than others, and those numbers are learned during training.

4 · MECHANISM & WHYOne output value, worked out by hand✓

Step 1 — in plain words

Put the filter on top of one patch of the image. The filter and the patch are the same size (say 3 by 3). Multiply each filter number by the image number right under it. Add all those products. That single sum is one output number. Then move the filter one step and do it again.

Step 2 — the formula

🧮
out = Σ ( image_patch[i][j] × filter[i][j] )
# Σ means "add up over every cell i, j in the patch"

Symbols: image_patch[i][j] = the image number at row i, column j under the filter. filter[i][j] = the filter weight at the same spot. Σ = add every product together. One patch in, one number out.

Step 3 — a worked 3×3 example

Say the image patch and the filter are these small 3 by 3 grids:

🔢
patch = [[1, 2, 0], [0, 1, 3], [2, 1, 0]]
filter = [[0, 1, 0], [1, 0, 1], [0, 1, 0]] # a plus-shape detector

products (only where filter = 1):
  2 (top) + 0 (left) + 3 (right) + 1 (bottom) = 6

out = 6 # one number for this patch

Only the plus-shaped cells count (the filter is 1 there, 0 elsewhere). Adding the four kept numbers 2 + 0 + 3 + 1 gives 6. That 6 is how strongly the "plus" pattern showed up in this patch. Slide the filter to the next patch and you get the next output number.

Why this is a big deal

  • Few weights: a 3×3 filter has only 9 numbers, not millions. Weight sharing reuses them everywhere.
  • Keeps neighbors together: because the filter looks at a patch, it uses the fact that nearby pixels belong together.
  • Finds patterns anywhere: a filter that spots an edge on the left also spots it on the right — one learned pattern, used across the whole image.
🔗
The big picture: stack many such filters and layers, and the network builds up from tiny edges to shapes to whole objects. Pooling between layers keeps the maps small so this stays fast. Every image model you have heard of starts from exactly this idea.
