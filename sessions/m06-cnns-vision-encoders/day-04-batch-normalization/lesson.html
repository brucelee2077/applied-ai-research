Module 6 · Represent · Day 4

BatchNormalization

Deep networks are hard to train because the numbers flowing between layers keep drifting — sometimes too big, sometimes too small — and every layer has to keep chasing a moving target. Batch normalization fixes this. After a layer, it re-centers and re-scales the numbers so each channel arrives clean and steady. Training gets faster and much more stable.

🎯
By the end, you'll be able to: explain what batch normalization does (normalize each channel across the batch using its mean and variance, then scale and shift), and say why it speeds and stabilizes training.
1Re-centering the numbers between layersWhat is it
🧭
What this assumes: the training loop and mini-batches from M5, and the CNN blocks from Day 3. Today we add one helper layer that makes those blocks train faster.

The problem

Inside a deep network, the numbers coming out of one layer feed into the next. As training changes the weights, those numbers keep shifting — one batch they are tiny, the next they are huge. Every layer then has to keep adjusting to a moving input. This makes training slow and shaky.

The fix: batch normalization

Batch normalization (often "batchnorm") sits between layers. For each channel, it looks at all the examples in the current mini-batch, then re-centers and re-scales those numbers to a clean, standard range.

Two steps

  • Normalize: subtract the batch mean and divide by the batch spread (the standard deviation). Now each channel is centered near 0 with a steady size.
  • Scale and shift: multiply by a learned number and add another learned number, so the network can undo the normalization if it turns out to be better.

The result: clean, steady inputs to every layer, so training moves faster and does not wobble. Keep going 👇

😕
为什么这里容易卡住 · Why this trips people up: batchnorm 在训练和测试时"行为不一样"，而且一张图的输出竟然依赖同批次里的别的图——这两点最反直觉。In plain terms: people expect a layer to treat each input independently, but batchnorm normalizes using the whole batch's mean and variance, and it uses batch stats while training but saved running averages at test time. That "same image, different answer depending on its batch-mates" behaviour is what feels wrong until you see the two modes.
2Re-centering the class after every quizIntuition
📊
The class scores drift

Imagine a class taking a quiz every day. One day everyone scores around 90, the next around 40, because the quiz got harder. A teacher who only looks at raw scores cannot tell who improved — the whole scale keeps moving.

⚖️
Re-center each time

So the teacher re-centers every quiz: shift so the average is 0, and rescale so the spread is the same each day. Now scores are comparable, and real progress shows through. Batchnorm does this to each channel, every batch.

In one line: batchnorm keeps the numbers between layers on a steady scale, so each layer always sees a familiar range instead of a moving target.

直觉 / Intuition: 就像每次考试都按"平均分归零、分差统一"来打分，让进步看得出来。In systems terms: it is auto-gain-control on the signal between layers — a normalize step re-centers and re-scales the values, then two learned knobs (γ, β) let the network turn that adjustment back up or down if it wants.

Because the inputs stay steady, you can safely use a bigger learning rate and train in fewer steps. That is the speed-up.

⚠️
Where the analogy breaks: a teacher re-centers using every student's score at once. Batchnorm only sees one mini-batch at a time, so its mean and spread are estimates. That is why, at test time, it uses a saved running average instead of a single batch — and why very tiny batches make batchnorm noisy.

4The formula, worked on small numbersMechanism & why

Step 1 — in plain words

Take one channel's values across the batch. Find their mean (average) and their variance (spread). Subtract the mean so they center at 0. Divide by the spread so they have a standard size. Then multiply by a learned number (gamma) and add a learned number (beta), so the network keeps control.

Step 2 — the formula, symbol by symbol

🧮
x_norm = (x − μ) / sqrt(σ² + eps)
y = γ · x_norm + β
  • x = one value in the channel; μ = the channel's mean over the batch.
  • σ² = the channel's variance (average squared distance from the mean).
  • eps = a tiny number so you never divide by zero.
  • γ (gamma) = a learned scale; β (beta) = a learned shift.

Step 3 — a worked example

Say one channel across a batch of 4 has values [2, 4, 6, 8]. Take gamma = 1, beta = 0 for now:

🔢
mean μ = (2+4+6+8)/4 = 5
var σ² = ((−3)²+(−1)²+(1)²+(3)²)/4 = 20/4 = 5
sqrt(σ²) ≈ 2.236

x_norm = [(2−5), (4−5), (6−5), (8−5)] / 2.236
       = [−1.34, −0.45, 0.45, 1.34]

y = 1·x_norm + 0 = same # mean 0, spread 1

The messy [2, 4, 6, 8] became a tidy set centered at 0 with a standard spread. Gamma and beta start at 1 and 0, so at first batchnorm just normalizes; during training the network learns better values if it needs them.

🪜
Math Ladder — batch normalization
1 · In words: center each channel at 0, rescale to a standard spread, then let two learned knobs re-scale and re-shift.
2 · The formula: x_norm = (x − μ)/√(σ² + ε), then y = γ·x_norm + β — μ,σ² = this channel's mean/variance over the batch; ε = tiny anti-divide-by-zero; γ,β = learned scale/shift.
3 · Tiny numbers: [2,4,6,8] → μ=5, σ²=5, √σ²≈2.236 → x_norm=[−1.34,−0.45,0.45,1.34]; with γ=1,β=0, y=x_norm.
4 · Sanity check: after normalizing, the channel's mean must be ≈0 and its std ≈1 (before γ,β); and setting γ=√σ², β=μ recovers the original x exactly — so the network can always undo the normalization if that's better.

Why it helps

  • Faster training: steady inputs let you use a larger learning rate, so you reach a good model in fewer steps.
  • More stable: layers no longer chase a moving input range, so the loss curve is smoother.
  • A little regularizing: the batch mean/variance are slightly noisy, which gently discourages overfitting (like a mild version of dropout).
⚠️
Train vs test: during training, batchnorm uses the current batch's mean and variance. At test time it uses a saved running average, so a single test image gets a consistent answer. Forgetting to switch to eval mode is a classic bug.

The staff lens — one silent failure, one trade-off

Batchnorm behaves differently in training and evaluation, and it quietly makes every image in a batch depend on the others — both bite when you are not watching.

⚠️
Failure mode (silent): running inference without switching to eval mode. If you forget to put the model in eval mode (model.eval()) before testing or serving, batchnorm keeps using the current batch's mean and variance instead of the saved running averages. Nothing crashes. But now a prediction depends on whatever other images happen to share the batch, so the same image gets different answers in different batches, and a batch of size 1 normalizes against itself and comes out near zero. Your training curves looked great, so the accuracy drop at serving time is a mystery. A senior engineer, in code review, checks that eval() is called (and gradients disabled) on every inference and validation path.
⚖️
Trade-off: batchnorm's speed-up costs you a dependence on batch size. The stable, well-scaled inputs that let you train faster come from statistics computed across the batch — so each example's output now depends on its batch-mates. With a healthy batch that noise is mild and even helps regularize. With a tiny batch (say 2–4 images, common when the model or images are large) the mean and variance are so noisy that training destabilizes. Whether to accept that coupling — or switch to a batch-independent normalizer like GroupNorm or LayerNorm — is the design-review decision when batch size is forced small.
🎤
Say this in an interview: "Batchnorm normalizes each channel across the batch — (x−μ)/√(σ²+ε) — then applies a learned scale and shift γ,β, so every layer sees a steady input range and you can train with a bigger learning rate. The nuance is the train/eval split and the batch coupling: at test time it must use saved running averages (forgetting model.eval() makes one image's prediction depend on its batch-mates, silently), and with tiny batches the stats are too noisy — that's when I reach for GroupNorm or LayerNorm instead."
