Module 22a · Generate · Day 1

Autoencoders

A photo of a face is thousands of numbers. But you can describe that face in a few words: "smiling, glasses, short hair". An autoencoder learns to do exactly that on its own. One part squeezes the image down to a tiny list of numbers. Another part rebuilds the whole image from just that tiny list. The squeeze forces the network to keep only what truly matters. This is the first step toward machines that create new pictures.

🎯
By the end, you'll be able to: explain an autoencoder as an encoder that squeezes an image into a small code and a decoder that rebuilds it, say why the small bottleneck forces the network to keep only what matters, and compute a reconstruction loss (MSE) on a tiny example by hand.
1Squeeze the image, then rebuild itWhat is it
🧭
What this assumes: you know that an image is a grid of numbers (pixels), and you know the training loop from M4–M6 — a network makes an output, a loss measures the error, and gradients nudge the weights. Today you meet a network whose job is to copy its own input.

A network that copies itself

An autoencoder is a neural network with one strange goal: take an image in, and put the same image out. That sounds useless. Why train a network to copy? The trick is what happens in the middle.

The two halves

The network has two parts. The encoder reads the image and shrinks it down to a short list of numbers. The decoder takes that short list and tries to rebuild the full image. In goes a big image, out comes a big image, but in the middle everything must pass through a narrow gap.

The narrow gap: the bottleneck

That short list in the middle is the latent code. The place where the network is forced to be small is the bottleneck. Say a face is 4096 numbers but the bottleneck is only 16 numbers. The decoder must rebuild all 4096 from just 16. So the encoder cannot keep everything — it must throw away the noise and keep only the parts that matter most.

How does it learn? Reconstruction loss

You measure how close the rebuilt image is to the real one. This gap is the reconstruction loss. A common one is MSE (mean squared error): subtract each rebuilt pixel from the true one, square it, average over all pixels. Training pushes this loss down, so the copies get sharper. Keep going 👇

2Zipping a file, then unzipping itIntuition
🗜️
Zip: the encoder

You have a big folder on your computer. You zip it into one small file to save space. Zipping finds patterns and repeats and packs them tightly. The encoder does this to an image: it packs a big picture into a tiny code.

📂
Unzip: the decoder

Later you unzip the small file and get your folder back. The decoder does this: it takes the tiny code and unpacks it back into a full image. If unzip gives you back what you zipped, the pair worked.

In one line: an autoencoder learns its own zip-and-unzip for images. The zipped file is the latent code; the goal is that unzipping brings the picture back.

The bottleneck is the size limit on the zip file. If you force the zipped file to be tiny, you cannot keep every detail. You must keep the important shape and drop the noise. That pressure is what makes the network learn what matters in a face — not the exact speck of dust, but the eyes, nose, and smile.

⚠️
Where the analogy breaks: a real zip file is lossless — unzip gives back the exact same bytes. An autoencoder is usually lossy — the rebuilt image is close but not perfect, a little blurry. The network learns a squeeze that keeps meaning, not every pixel.

4The reconstruction loss, worked out by handMechanism & why

Step 1 — in plain words

The encoder turns the input x into a small code z. The decoder turns z back into a rebuilt image, called x̂ (say "x-hat"). To score the rebuild, you compare x̂ to the real x, pixel by pixel. For each pixel, take the difference, square it (so the sign does not matter and big misses hurt more), then average over all pixels. That average is the loss.

Step 2 — the formula

🧮
z = encoder(x) # big image → small code
x̂ = decoder(z) # small code → rebuilt image
loss = (1/N) · Σ ( x[i] − x̂[i] )²
# Σ adds over every pixel i; N = number of pixels

Symbols: x[i] = the true value of pixel i. x̂[i] = the rebuilt value of pixel i. N = how many pixels. Σ = add up over all pixels. Squaring makes every gap positive and punishes big misses harder than small ones.

Step 3 — a worked example with 4 pixels

Say the true tiny image and the rebuilt one are these 4 numbers each:

🔢
x = [0.8, 0.2, 0.5, 1.0] # true pixels
x̂ = [0.7, 0.4, 0.5, 0.8] # rebuilt pixels

differences: 0.1, −0.2, 0.0, 0.2
squared: 0.01, 0.04, 0.00, 0.04
sum = 0.09 N = 4

loss = 0.09 / 4 = 0.0225

The rebuilt pixels are close but not perfect. Squaring the gaps gives 0.01, 0.04, 0.00, 0.04. They add to 0.09. Dividing by the 4 pixels gives 0.0225. Training nudges the encoder and decoder weights to make this number smaller, so future rebuilds match better.

Why the bottleneck is the whole point

  • Forced choice: the code is much smaller than the image, so the encoder cannot keep everything. It must keep only what helps the decoder rebuild well.
  • Learns structure: to survive the squeeze, the network discovers the real patterns — the shape of a face, not random noise.
  • Useful code: that small code is a compact summary of the input. You can use it to compress, to find similar images, or as a starting point for generating new ones.
🔗
The big picture: an autoencoder gives you a small, meaningful code for any input. But a plain code is just a point — you cannot easily invent new points that decode into new faces. Tomorrow's VAE fixes this by making the code a distribution, so you can sample brand-new codes and generate brand-new images.
