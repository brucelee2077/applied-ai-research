Module 22a · Generate · Day 2

The VAE

Yesterday's autoencoder squeezed an image into a single point — one exact code. But a single point is a dead end: you cannot easily invent new codes that decode into new images. The VAE fixes this. Instead of one point, the encoder outputs a small cloud — a mean and a spread. You sample a code from that cloud, so nearby codes decode into similar images, and you can generate brand-new ones. The clever part that makes training possible is called the reparameterization trick.

🎯 By the end, you'll be able to: explain why the encoder outputs a mean μ and standard deviation σ instead of one point, write the reparameterization trick z = μ + σ·ε and say why it lets gradients flow, and describe the ELBO as a reconstruction term plus a KL term that pulls the latent toward a standard normal.
1 · WHAT IS ITA code that is a cloud, not a point✓
🧭
What this assumes: you know Day 1 — an autoencoder squeezes an image into a code and rebuilds it with reconstruction loss. Today you change one thing: the code becomes a small random cloud instead of one fixed point. That one change lets you generate new images.

The problem with a plain code

A plain autoencoder maps each image to one exact code. The space between codes is a mess — pick a random code and the decoder often makes garbage. So you cannot reliably invent new images by picking new codes. You need the code space to be smooth and full.

The fix: output a distribution

A VAE (variational autoencoder) changes the encoder. Instead of one code, the encoder outputs two things for each latent number: a mean μ (the center) and a standard deviation σ (how wide the cloud is). Together they describe a small distribution — a fuzzy region, not a single dot.

Sample a code from the cloud

To get an actual code z, you draw a random sample from that cloud. Two images that look alike get overlapping clouds, so their codes land near each other. This makes the code space smooth: nearby codes decode into similar images.

Why this unlocks generation

During training a second force, the KL term, gently pulls every cloud toward one shared, simple shape: the standard normal N(0,1). After training, you can pick a random code straight from N(0,1), hand it to the decoder, and out comes a brand-new, believable image. That is generation. Keep going 👇

2 · INTUITIONDescribe a face by ranges, then roll dice✓
📏
Ranges, not exact numbers

Instead of saying "the nose is exactly 3.7 cm", you say "the nose is around 3 to 4 cm". You give a center (about 3.5) and a spread (give or take 0.5). That center is μ. That spread is σ. Each face feature becomes a small range, not one fixed number.

🎲
Roll dice inside the range

Now to actually draw the face, you roll dice inside each range to pick a value: maybe 3.6 this time, maybe 3.4 next time. Every roll gives a slightly different but believable face. The rolling is the sampling. Same ranges, many faces.

In one line: the encoder describes each image as a set of ranges (means and spreads), and you roll dice inside those ranges to get one code, which the decoder turns into an image.

Because you describe images as overlapping ranges, similar images share overlapping ranges. So the whole code space fills in smoothly — you can pick any code, even one you never trained on, and get a sensible image. That is the difference from Day 1's single fixed point.

⚠️
Where the analogy breaks: real dice are fair and fixed. Here the "dice" are a standard normal bell curve (values near the center are more likely than the edges), and the ranges (μ and σ) are learned during training, not decided by you.

4 · MECHANISM & WHYThe reparameterization trick, worked out by hand✓

The problem: you cannot train through a random draw

The VAE samples a code z from the cloud. But sampling is random. To train, you need gradients — a chain of "if I nudge this weight, the loss changes by this much". You cannot take a gradient through a plain random draw, because "pick a random number" has no smooth handle to nudge. Training would stop right here.

Step 1 — the trick, in plain words

Move the randomness to the outside. First draw one plain random number ε (say "epsilon") from the fixed standard normal N(0,1). Then build the code by scaling and shifting that ε: multiply by σ, add μ. Now the only random part is ε, which has no weights. The parts that carry weights — μ and σ — are plain multiply and add, so gradients flow straight through them.

Step 2 — the formula

🧮
μ, σ = encoder(x) # the cloud's center and spread
ε ~ N(0, 1) # one plain random draw, no weights
z = μ + σ · ε # the reparameterization trick
# randomness sits only in ε; μ and σ stay differentiable

Symbols: μ = the mean, the center of the cloud. σ = the standard deviation, the spread. ε = a random draw from N(0,1), the fixed standard bell curve. z = the final sampled code fed to the decoder. Because μ and σ only appear in a multiply and an add, the gradient can pass through them to the encoder's weights.

Step 3 — one reparameterized sample, worked out

Say the encoder gives μ = 2.0 and σ = 0.5 for one latent number, and the random draw happens to be ε = 1.2:

🔢
μ = 2.0 σ = 0.5 ε = 1.2 # ε drawn from N(0,1)

z = μ + σ · ε
z = 2.0 + 0.5 · 1.2
z = 2.0 + 0.6
z = 2.6 # one sampled code number

The code is 2.6 this time. Draw a new ε next time (say 0.4) and you get z = 2.0 + 0.5·0.4 = 2.2 — a slightly different code near the same center. The center 2.0 and spread 0.5 came from weights, so training can still nudge them. The wobble came from ε, which is just noise.

The full loss: the ELBO

The VAE trains on the ELBO, which has two parts that pull in different directions:

🧮
loss = reconstruction_term + KL( q(z|x) ‖ N(0,1) )
# term 1: rebuild x well from z (like Day 1's MSE)
# term 2: keep each cloud q(z|x) close to the standard normal
  • Reconstruction term: the same "rebuild the image well" pressure as Day 1. It wants clouds that decode back to the right picture.
  • KL term: pulls each encoder cloud q(z|x) toward the shared prior N(0,1). It stops clouds from drifting far apart and keeps the code space smooth and full.
⚠️
The two terms fight. Pure reconstruction wants sharp, spread-apart codes (like Day 1). Pure KL wants every cloud to be exactly N(0,1), which forgets the image. The balance between them is what makes a VAE both rebuild and generate.
🔗
The big picture: the reparameterization trick is the one idea that made VAEs trainable — it lets you take gradients through a random sample. Tomorrow's VQ-VAE hits the same "cannot differentiate" wall, but at a different step (snapping to a codebook), and solves it with a related trick: the straight-through estimator.
