Module 22a · Generate · Day 3

VQ-VAE

The VAE's code was a cloud of real numbers. Today we make the code a choice from a menu. The encoder still turns an image into a vector, but then that vector snaps to the nearest entry in a small, learned list called a codebook. The code becomes discrete — a slot number, like picking the closest paint tube instead of mixing an exact color. That snap hits the same "cannot take a gradient" wall the VAE hit, and we fix it with a close cousin of yesterday's trick: the straight-through estimator.

🎯
By the end, you'll be able to: explain what a codebook is and why snapping to the nearest entry makes the latent code discrete, say why the snap has no usable gradient and how the straight-through estimator copies the gradient past it, and name the three parts of the VQ-VAE loss (reconstruction, codebook, commitment).
1A code that picks from a menuWhat is it
🧭
What this assumes: you know Day 2 — a VAE's encoder outputs a cloud (μ, σ) of continuous numbers and samples a code from it. Today the code stops being continuous. It becomes one of a fixed set of learned vectors. That one change is what powers the tokenizers behind image and audio generators.

Continuous vs discrete codes

A VAE code is a list of real numbers — it can be 2.6, or 2.61, or any value in between, endless choices. A VQ-VAE (vector-quantized VAE) forces the code to be one of a small, fixed set of vectors. Instead of "any number", the code becomes "slot #7 from a menu of 512".

The codebook

That menu is called the codebook: a learned table of, say, 512 vectors. The encoder produces a normal continuous vector, then quantization replaces it with whichever codebook vector sits closest. The decoder only ever sees codebook vectors.

Why anyone wants discrete codes

Once each image is a grid of slot numbers (like [7, 12, 7, 3, ...]), you can treat those numbers exactly like words in a sentence. You can train a second model — the same kind of transformer you built earlier — to predict the next slot number. That is how DALL·E-style and many audio generators work: turn the picture into discrete tokens with a VQ-VAE, then let a language model write new token sequences.

The catch we must solve

Picking "the nearest entry" is a hard choice with a sharp edge. As you will see, you cannot take a smooth gradient through a hard choice — so training would break right at the snap. The rest of today is about slipping past that wall. Keep going 👇

2Snap each color to the nearest paint tubeIntuition
🎨
A fixed box of paints

You want to repaint a photo, but you only own 512 paint tubes. For each spot in the photo you pick the tube whose color is closest to what you see. The photo is now described entirely by tube numbers. That box of tubes is the codebook; picking the closest tube is quantization.

🔢
The photo becomes numbers

Now the whole picture is a grid of tube numbers: "tube 7 here, tube 12 there". That short list of numbers is small and tidy — perfect for a second model to learn to write new lists, which decode into new pictures.

In one line: the encoder proposes a color, the codebook snaps it to the nearest tube, and the picture turns into a grid of tube numbers you can later generate.

This is the big shift from Day 2. The VAE's code was smooth and continuous, so you sampled from a cloud. The VQ-VAE's code is a slot number, so you generate by predicting slot numbers — a totally different, and very powerful, path to new images.

⚠️
Where the analogy breaks: real paint tubes are fixed colors you buy. Here the codebook vectors are learned during training — they slowly move to match the kinds of patterns the encoder tends to produce.

4The straight-through estimator and the three-part lossMechanism & why

The wall: a hard choice has no gradient

Snapping means "of all codebook vectors, pick the closest one". That is an argmin — a jump between whole slot numbers. Nudge the encoder's output a tiny bit and the chosen slot usually does not change at all; nudge it a hair more and it suddenly flips to a different slot. A function that is flat then jumps has a gradient of zero almost everywhere. So gradients cannot flow back through the snap, and the encoder would never learn.

Step 1 — the fix in plain words

Use the snapped code z_q in the forward pass, so the decoder sees a real codebook vector. But in the backward pass, act as if the snap were an identity (a do-nothing step) and hand the decoder's gradient straight back to the encoder's continuous output z_e. You skip over the un-differentiable snap. This is the straight-through estimator (STE).

Step 2 — the one-line code that does it

🧮
z_e = encoder(x) # continuous vector
z_q = nearest_codebook_vector(z_e) # the hard snap (no gradient)
z_q = z_e + (z_q - z_e).detach() # the straight-through trick
# forward: value == z_q. backward: gradient flows to z_e as if identity.

Symbols: z_e = the encoder's continuous output. z_q = the snapped codebook vector fed to the decoder. .detach() = "block gradients through this part". Because (z_q − z_e) is detached, its gradient is zero, so the gradient of z_q equals the gradient of z_e — the gradient passes straight through.

Step 3 — one snap, worked out by hand

Say the codebook has three vectors and the encoder outputs z_e = [0.9, 0.2]. Snap = pick the one with the smallest squared distance:

🔢
codebook: e1=[1.0, 0.0] e2=[0.0, 1.0] e3=[0.5, 0.5]
z_e = [0.9, 0.2]

dist² to e1 = (0.9-1.0)² + (0.2-0.0)² = 0.01 + 0.04 = 0.05
dist² to e2 = (0.9-0.0)² + (0.2-1.0)² = 0.81 + 0.64 = 1.45
dist² to e3 = (0.9-0.5)² + (0.2-0.5)² = 0.16 + 0.09 = 0.25

nearest = e1 → z_q = [1.0, 0.0], slot index = 1

The code is now "slot 1" — a single integer that stands in for the whole vector. The decoder rebuilds the image from e1, and the STE lets the encoder still learn to point at good slots.

The full loss: three parts

🧮
loss = recon(x, x̂) # 1. rebuild the image from z_q
   + ‖ sg[z_e] − e ‖² # 2. codebook loss: move e toward z_e
   + β · ‖ z_e − sg[e] ‖² # 3. commitment: keep z_e near its code
  • Reconstruction: rebuild x well from the snapped code — the STE makes this train the encoder too.
  • Codebook loss: pull the chosen codebook vector e toward the encoder output. (sg = stop-gradient, so only e moves here.)
  • Commitment loss: pull the encoder output toward its chosen code so it does not wander between slots. β (often 0.25) sets how strong this pull is.
⚠️
Silent failure — codebook collapse. A common, quiet failure is that only a handful of the 512 codebook entries ever get used; the rest sit dead. Reconstruction still looks okay, so nothing screams — but you have thrown away most of your capacity, and your discrete tokens are far less expressive than the codebook size suggests. Watch codebook usage (how many entries fire), not just the loss. Common fixes: restart dead codes, use exponential-moving-average codebook updates, or lower the commitment β.
⚖️
Trade-off — discrete vs continuous. Discrete codes buy you a huge win: images become token sequences a transformer can generate, and reconstructions are often sharper than a VAE's blurry average. You pay for it with training complexity — a non-differentiable snap needing the STE, a codebook that can collapse, and an extra generative model on top. A plain VAE is simpler to train but its samples are blurrier and it has no natural token vocabulary.
🔗
The big picture: Day 2's reparameterization trick and today's straight-through estimator solve the same problem — "how do I train through a step I cannot differentiate?" — in two settings: a random sample, and a hard discrete choice. Tomorrow's GAN drops reconstruction entirely and learns purely from a second network's judgment.
