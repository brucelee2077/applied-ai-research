Module 5b · Represent · Day 4 (finale)

The ViT Classifier

The module finale. Your patches have gossiped through the blocks and the class token is now full of notes about the whole image. One last step: read out that single token and run it through a small classifier head to get 10 scores — one per CIFAR-10 class. You will also learn the honest truth about ViTs: they are hungry, and on small data a simple CNN often beats them.

🎯 By the end, you'll be able to: take the class-token output into a linear classifier head, assemble a small end-to-end ViT for CIFAR-10, and explain when ViTs beat CNNs and when they trail them (data-hungry).
1 · WHAT IS ITFrom the class token to a prediction✓
🧭
What this assumes: Days 1–3 (patchify, patch embedding + class token + position, and the transformer block stack), plus the loss and training loop you built in M5a. Today you add the final head and put the whole ViT together.

The last step: read one token, then classify

After the transformer blocks, you have a (65, 128) sequence. You throw away 64 of the 65 tokens and keep only the class token — row 0. Why? Because attention already wrote a summary of the whole image into it. You feed that one 128-length vector into a classifier head — a single Linear(128, 10) — to get 10 logits, one per class.

The whole ViT, front to back

Put together, the full model is: image → patchify → patch embedding + class token + position → N transformer blocks → take the class token → classifier head → 10 logits. Every piece is something you already built across Days 1–3 and M5a. Today just snaps on the last block.

The honest truth: ViTs are data-hungry

Here is the part people skip. A ViT has almost no built-in assumption that nearby pixels are related. A CNN has that assumption baked in, so it learns from small datasets quickly. A ViT must learn everything from the data — so on a small set like CIFAR-10 trained from scratch, a simple CNN often beats it. Give a ViT huge data (millions of images), though, and it pulls ahead. Keep going 👇

2 · INTUITIONA committee vote read off the chairperson✓

Picture a committee meeting. Around the table sit 64 members, each having seen only their own patch of the photo. In the chair sits one extra person — the class token — who does not own a patch but listens to everyone. Through the meeting (the transformer blocks) the chairperson gathers everyone's views. At the end, you do not poll all 64 members. You just ask the chairperson: "So, what is it?" Their one answer becomes the decision.

🪑
chairperson = class token

The class token sits in the chair, listens to all patches, and holds the summary. Its final state is the one you read out.

🗳️
the head = the final vote count

The classifier head turns the chairperson's summary into 10 scores. The highest score is the committee's answer — the predicted class.

In one line: the class token is the chairperson who gathered every patch's view, and the classifier head reads that one summary out as the final class scores.

⚠️
Where the analogy breaks: a real chairperson can only listen to a few people well before getting overwhelmed. The class token has no such limit — attention lets it take in all 64 patches at full strength at once. And unlike a human chair, it needs a lot of practice (data) before its "summaries" are any good.

4 · MECHANISM & WHYThe head, the full model, and the CNN trade-off✓

Step 1 — in words

Take the (65, 128) output of the blocks. Slice out row 0, the class token — that is one vector of length 128. Run it through a single linear layer that maps 128 down to 10. The 10 outputs are logits: raw class scores. The biggest one is your prediction.

Step 2 — the formula, every symbol labeled

🧮
cls_out = x[0] # row 0 of (65,128) → shape (128,)
logits = Linear(128,10)(cls_out) # → shape (10,)
pred = argmax(logits) # the biggest score is the class
  • x = the block output, shape (65, 128) · x[0] = the class token, shape (128,)
  • Linear(128, 10) = the classifier head, one score per CIFAR-10 class
  • logits = the 10 raw scores · argmax = the index of the biggest score, the prediction

Step 3 — a worked example with small numbers

Say the head outputs these 10 logits: [0.1, 2.9, 0.3, ..., 0.2].

  • The biggest value is 2.9, at index 1.
  • CIFAR-10 index 1 is "automobile", so the model predicts automobile.
  • During training you compare these logits to the true label with cross-entropy loss (from M5a) and update every weight.

💡 ViT vs CNN — the trade-off

SituationWinnerWhy
Small data (CIFAR-10 from scratch)CNNCNNs assume nearby pixels relate, so they learn from little data
Huge data (millions of images)ViTWith enough data the ViT learns better, more flexible features

⚠️ Gotchas

  • Only the class token feeds the head. x[0], not all 65 rows. The patches matter only through what attention wrote into that one token.
  • Do not expect state-of-the-art on CIFAR-10 from scratch. A small ViT here is a learning exercise; a CNN would likely score higher on this small set.
  • Overfit one batch first. Before full training, train on a single tiny batch until the loss drops near zero. That proves gradients flow through the whole ViT before you spend hours on the full set.
