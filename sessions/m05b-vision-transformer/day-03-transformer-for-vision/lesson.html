A Transformer for Vision

Here is the surprise: you do not build a new model for images. The transformer block you already built for text works on patches without changing a single line. Feed the (65, 128) patch sequence in, and attention lets every patch look at every other patch — the top-left corner can compare notes with the bottom-right. Same block, new job.

🎯
By the end, you'll be able to: feed the patch sequence through the same transformer block from M5a, explain that attention now mixes information across image regions, and show that the shape never changes through the blocks.
1The same transformer block, now reading patchesWhat is it
🧭
What this assumes: Day 2 (the image is a (65, 128) sequence with a class token and position), and the transformer block you built in M5a — LayerNorm, attention, residual add, MLP. Today you learn that block needs zero changes for vision.

The big idea: no new model

A transformer block takes a sequence of vectors and returns a sequence of the same shape. It does not care whether those vectors came from words or from image patches — they are just numbers in a list. So the exact block from M5a runs on your (65, 128) patch sequence with nothing changed.

What attention does with patches

Inside the block, attention lets every token look at every other token. For text, this is one word checking other words. For vision, it is one patch checking every other patch. The sky patch can notice the bird patch. The class token can gather from all 64 patches at once. This mixing across regions is the whole point.

Stacking blocks

You do not run just one block — you stack several, one after another. Each block lets patches read from each other again, building richer and richer understanding. Through every block the shape stays (65, 128): the number of tokens and their size never change, only the content each token holds.

Why this is the payoff

Days 1 and 2 did all the vision-specific work: cutting patches, embedding, position. Once that is done, vision reuses the text transformer completely. One architecture, two very different inputs. That reuse is exactly why transformers took over so many fields. Keep going 👇

2Patches gossiping about what each other seesIntuition

Imagine each patch is a person standing in a room, and each one can only see their own little square of the photo. On their own, none of them knows what the picture is. So they talk. Each person asks everyone else, "what do you see?" and blends the useful answers into their own notes. After a few rounds of this gossip, each person has a much fuller picture — and the class token, who was taking notes the whole time, can tell you what the image is.

🗣️👥
gossip round = attention

Each patch asks every other patch what it sees and blends in the useful parts. One round of gossip is one attention step inside a block.

🔁
several rounds = stacked blocks

One conversation is not enough. Stacking blocks is running several gossip rounds, so understanding builds up layer by layer.

In one line: attention lets patches gossip so each one learns what the others see, and stacking blocks runs that gossip several times to build a full understanding.

⚠️
Where the analogy breaks: real gossip is one-on-one and slow. Attention is not — every patch talks to every other patch at the same time, in one matrix multiply. There is no taking turns; it all happens at once.

4Inside the block, and why the shape holdsMechanism & why

Step 1 — in words

One transformer block does six small things in order: LayerNorm (steady the numbers), attention (patches read each other), a residual add (keep the original around), LayerNorm again, a small MLP (think per token), and another residual add. Then you stack N of these. Attention is the only step that lets tokens talk; everything else works on each token by itself.

Step 2 — the formula, every symbol labeled

🧮
x = x + attention(LayerNorm(x)) # patches mix, then add back
x = x + mlp(LayerNorm(x)) # per-token thinking, then add back
# repeat this whole block N times; x stays (65, 128)
  • x = the token sequence, shape (65, 128) going in and coming out
  • attention(...) = the mixing step, where every token reads from every other
  • mlp(...) = a small two-layer network applied to each token on its own
  • x + ... = the residual add that keeps the original signal safe

Step 3 — a worked example with small shapes

Say x has shape (65, 128) and you stack 6 blocks.

  • Block 1: in (65, 128) → out (65, 128). Same shape, richer content.
  • Blocks 2–6: each one again (65, 128) → (65, 128).
  • After all 6: still (65, 128). The token count and size never changed — only what each token knows.

⚠️ Gotchas

  • Attention never resizes. It mixes information between tokens but returns the same shape. If your sequence length or embedding size changes inside a block, something is wrong.
  • Residual adds need matching shapes. x + attention(...) only works because the block returns exactly x's shape. This is why the size is held fixed the whole way.
  • More blocks is not always better. On small data, a deep stack overfits fast. ViTs are hungry — you will see why on Day 4.
🔗
Why this matters: the text transformer and the vision transformer share this exact block. The only difference between them is the input: word tokens versus patch tokens. Tomorrow you read out the class token and turn all this mixing into an actual prediction.

The staff lens — one silent failure, one trade-off

Because the block returns the same shape it was given, the nastiest bug is one that keeps the shape but mixes along the wrong axis.

⚠️
Failure mode (silent): attention mixing along the wrong axis. PyTorch's nn.MultiheadAttention defaults to batch_first=False — it expects (seq, batch, dim). If you feed it your patch sequence as (batch, seq, dim) = (1, 65, 128) and forget to set batch_first=True, it treats dimension 0 (your batch of 1) as the sequence. Attention then mixes over the wrong axis, but the output shape is still (1, 65, 128), so no assertion fails and training still runs. With batch size 1 the patches never actually attend to each other — the model quietly ignores cross-patch information and underperforms with no error to trace. A senior engineer catches this in code review by checking the batch_first setting against the tensor layout, or by feeding two known-different sequences in a batch and confirming each one's output does not depend on the other.
⚖️
Trade-off: every block re-pays the O(sequence²) attention cost. Attention lets every patch read every other patch, which costs on the order of tokens² per block. Stacking N blocks makes representations richer but multiplies that cost by N, and halving the patch size (4× more tokens) makes each block roughly 16× more expensive. Choosing how deep the stack goes and how many tokens you feed it is the design-review decision that trades accuracy for compute and memory.
