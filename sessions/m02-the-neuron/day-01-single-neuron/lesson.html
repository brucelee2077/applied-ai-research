A Single Neuron
The Smallest Piece of a Learning Machine

You can read shapes and multiply matrices. Now we build the thing those matrices actually power: a neural network. It's made of tiny units called neurons, and one neuron does just three small steps. Get the neuron, and a whole network is only "many of these."

🎯 By the end, you'll be able to: name the three steps a neuron does — weighted sum → add bias → activation — and compute one neuron's output by hand.
1 · WHAT IS ITWhat a neuron is (and what a network is made of)✓
🧭
What this assumes: Module 1 — arrays, the dot product / matmul (Day 4), and broadcasting. No neural-network background needed — this is the first piece.

What is a neural network?

A neural network is a machine that learns patterns from examples by tuning a big pile of numbers called weights. It is built from many tiny repeated units — neurons — stacked into layers. Today we zoom all the way in to one neuron.

What is a neuron?

A neuron is a tiny function with exactly three steps:

  1. Weighted sum — multiply each input by its weight and add them up. (This is exactly a dot product from M1 Day 4.)
  2. Add a bias — add one extra number, the bias, that shifts the result.
  3. Activation — pass that result through a simple function (an activation function) to get the output.

How does it relate to what you know?

Step 1 is something you can already do: np.dot(w, x) — the weighted sum is a dot product. So a neuron is just activation(dot(w, x) + b). Why the activation at the end? That's the secret sauce — next lesson. Keep going 👇

🏭
A real one: remember GPT-3's (12288, 49152) weight matrix from M1 Day 1? By the end of today you'll see exactly what each of its 49,152 columns really is.
2 · INTUITIONA judge scoring a contestant✓
⚖️
Inputs × weights = a judge's score

Each input (talent, stage presence…) gets a weight — how much this judge cares about it. The judge multiplies and adds them into one score.

🎚️
Bias + activation = the verdict

The judge has a personal bias (a grumpy judge starts lower), then squashes the total into a clean verdict with an activation.

In one line: a neuron weighs its inputs, adds a bias, and squashes the result into an output.

⚠️
Where the analogy breaks: a real brain neuron is far messier, and one artificial neuron alone is weak. The power comes from many neurons in layers — which is just a matmul, as you'll see at the end.

4 · MECHANISM & WHYThe formula — and why one neuron scales to billions✓

The formula

🧮
output = activation( w · x + b )
w · x = weighted sum (a dot product), b = bias (one number), activation = a simple squashing function like ReLU. The value w · x + b, before the activation, is called the pre-activation (often written z).

Worked small: inputs x = [2, 3], weights w = [0.5, −1], bias b = 1. Weighted sum = 2·0.5 + 3·(−1) = −2. Add bias → −1. ReLU(−1) = 0. Output = 0.

Why a frontier lab cares

This is the atom. Line up many neurons that all read the same inputs, and computing them all at once is a single matmul: x @ W + b, then the activation — exactly M1 Day 4. Here's the answer to the teaser above: every one of that GPT-3 matrix's 49,152 columns is one neuron like the one you just built, wired to 12,288 inputs instead of a handful. A frontier model is billions of these neurons, stacked into layers. And the weights are precisely what training adjusts.

🔗
Remember this chain: a neuron = weighted sum + bias + activation → many neurons at once = a matmul (a layer) → stacked layers = a network → training tunes the weights. Everything later is scale on top of this.

The staff lens — one silent failure, one trade-off

A neuron is tiny, but two things about it are worth naming precisely — a bug that never announces itself, and a design choice you make every time you build a layer.

⚠️
Failure mode (silent): the dead neuron. If a neuron's weights and bias make the pre-activation z = w·x + b come out negative for every input, then ReLU(z) is always 0. Look at the worked example: z = −1 gave output 0. If that happened for all inputs, the neuron would output the same 0 forever. Nothing crashes — the code runs fine — but that neuron computes nothing and adds no value to the network, so the model quietly runs at less than full strength. A senior engineer catches this in code review by printing the fraction of neurons whose output is stuck at zero; a healthy layer should have many neurons that actually change with the input.
⚖️
Trade-off: which activation you bolt on. Choosing ReLU buys you a cheap, fast squash (just a max) that trains well in deep stacks. You pay for it with the dead-neuron risk above, because everything below zero is flattened to exactly zero. A different activation that never fully flattens (its output keeps moving even for negative inputs) removes that risk, but costs a little more math per neuron. Which activation to use is a design-review decision, not a detail — it changes how many of your neurons actually do useful work.
