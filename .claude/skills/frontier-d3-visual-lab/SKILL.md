# Frontier D3 Visual Lab

> Often triggered from a daily quest page (the PRODUCE step) generated by
> `frontier-session-coach`. When invoked that way, build the visualization the quest
> describes at the path it gives.

Create interactive HTML/D3.js learning visuals.

## Output contract
Create:

```text
courseware/<topic-slug>/index.html
courseware/<topic-slug>/style.css
courseware/<topic-slug>/main.js
courseware/<topic-slug>/README.md
```

If a single-file page is better, create only:

```text
courseware/<topic-slug>/index.html
```

But still include clear code sections and comments.

## Visualization design principles
- Visualize one core mechanism, not everything.
- Make labels large and beginner-friendly.
- Add controls only when they teach something.
- Prefer sliders/toggles/buttons over decorative animation.
- Include short teaching text next to the visual.

> ⛳ **Ground Zero Rule.** Assume the viewer has zero prior knowledge of the concept being
> visualized (though they can program). Before the interactive, give a one-line "what is this
> and why" and define any term the visual uses. The page should teach, not just display.

## Good visual types

### Attention
- Tokens as nodes
- Attention weights as arrows or heatmap
- Slider for attention sharpness / temperature

### Scaling laws
- Log-log curve
- Sliders for model size, data size, compute
- Show undertraining vs compute-optimal intuition

### KV cache
- Timeline: prompt prefill → decode steps
- Cache blocks accumulate over time
- Show why not recomputing saves work

### MoE
- Tokens routed to experts
- Capacity factor / dropped tokens
- Dense vs sparse compute comparison

### Quantization
- Continuous values → lower precision buckets
- Show memory saving vs error

### Inference serving
- Request queue
- batching
- prefill/decode separation
- p50/p95 latency intuition

### Distributed training
- Devices as workers
- compute vs communication
- gradient all-reduce animation

## Required page sections
Every page must include:
1. What you are seeing
2. How to interact
3. Why this matters
4. One misconception to avoid
5. 3 quiz questions

## D3 loading
Prefer:

```html
<script src="https://cdn.jsdelivr.net/npm/d3@7"></script>
```

If the repo has a D3 skill or local vendor file, use it and mention the dependency in README.

## Accessibility
- Use semantic HTML.
- Do not rely only on color.
- Use readable font sizes.
- Include captions for diagrams.

## Done definition
The visualization must run locally by opening `index.html` in a browser, unless the user requests a bundled server setup.
